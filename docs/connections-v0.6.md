# 接入与自动草稿合同 v0.6

本页描述代码边界与合成验收，不声称真实网站账号或 Claude Code 宿主已验收。没有安装用户 Hook、连接用户账号或调用外部模型。

## 一次配置，两个不同层次

1. 本机安装/注册把客户端绑定到准确的扩展 ID、资料库及最大范围；生成文件不等于注册成功，注册成功不等于宿主已经调用。
2. 连接设置保存独立的读取范围、捕获范围、自动捕获、自动召回及资料接收方授权。原生桥已经注册后，扩展默认发送零权限的“请求桌面连接”；桌面显示发起安装与网站，用户一次选择独立范围并批准。待处理请求最多16个，10分钟过期，相同安装/网站重试复用原请求而不延长期限。批准前无读取或捕获权限。复制 `recallcard-connect/1:<extensionId>:<installationId>` 连接编号只作为手动备用。首次原生桥注册仍要求准确扩展 ID，并由用户完成受信任安装；配对请求不绕过浏览器安装安全边界。填写完成仍是 `configured_unverified`。每次修改增加 `permission_revision`；撤销使旧版本失效。

授权存放在本机状态目录，不进入 Event/Memory 正本或 Git。状态文件绑定资料库 marker 的原生文件身份及路径；在原路径换成新资料库不能继承旧授权。网页和模型动作没有创建/修改授权接口。Native只有排队待确认请求的能力，不能批准；本机批准会原子检查有效期、准确安装、网站和启动器范围上限。原生启动器的固定范围是另一道上限，连接设置不能突破。

浏览器授权同时绑定准确扩展 ID、本机安装编号（storage.local 中的随机 UUID）和所选网站，不是账号认证。相同扩展 ID 的另一个浏览器 profile、清除扩展存储或重新安装后生成的新编号，都需要独立设置，不能回退继承较宽的旧授权。安装编号不是网站凭据，也不防御控制本机操作系统账号的攻击者。扩展不读 Cookie、令牌或私有 API；`account_identity=unverified` 始终可见。导航、文档和输入框身份改变会废弃临时绑定，受支持页面稳定后自动重新绑定，持久授权不会因为新增一条消息而要求用户再批准。无法通过 DOM 可靠识别的同页账号切换不宣称已验证。

读取范围不自动授权捕获；本机保存不自动允许把私人内容提供给网站。`provider_disclosure` 明确表示所选网站可读取准备好的草稿，或所选 Agent 及用户已批准的模型服务可接收启动资料/读取结果。即使未点击 Send，网站也可能读取输入框，首次授权必须说明这一点。更换实际模型接收方仍需用户核对并重新授权，适配器不能认证宿主内部模型路由。

## ChatGPT 的原生读取路径

ChatGPT 网页支持官方自定义 MCP 插件；Secure MCP Tunnel 可以把本机 stdio 服务接入，服务器无需开放公网。RecallCard 已补独立的 `chatgpt_mcp` 只读授权与本机启动说明，复用四工具及当前范围/撤权检查；真实隧道、凭据和插件授权尚未配置。准确差距与验收入口见 [ChatGPT 原生接续](chatgpt-native-mcp.md)。

需要多轮人工 Send 是下面旧草稿协议的限制，不是 ChatGPT 网页本身的必然限制。原生工具结果无需借草稿逐次回传。DeepSeek 原网页版目前没有已核实的同等原生入口证据，应单独标为受限分支。

## 兼容 / 受限的 Web 草稿路径

- 只在前台活动标签页工作，不自动滚动，不访问隐藏历史、网络接口、推理、图片或附件原件。
- 先由可信 worker 检查本机持久授权，再读取文字。页面 MutationObserver 本身只观察身份和变化，不提前读取正文。
- 无流式标记且安静至少 1.5 秒后才生成候选；只保存明确 `user/assistant` 角色、稳定网站消息 ID 和稳定会话 ID 的片段。其余片段给出跳过/等待说明，不假装完整覆盖。DeepSeek 经常缺少稳定身份，因此可能只能自动保存一部分，人工预览仍可补充。
- 扩展自行插入的精确 RecallCard 标记块会被剔除，周围原有用户文字保留；损坏标记不冒充用户事实。
- 捕获经过本机脱敏、来源身份去重和当前授权核验后落盘。首次捕获失败不标记成功；同一快照再次尝试由事实源去重。大快照按 Native Messaging 帧限额拆块；超大单消息明确停止、不截断。
- 新的已绑定会话自动准备稳定 Bootstrap；后续只读取最后一条已完成、身份明确的助手消息中的完整 `recallcard-action` 块，执行 `bootstrap/search/read/sources` 四种只读能力。未知/重复/跨会话/未完成/写操作请求都不执行。
- 结果重新核验后追加到可见草稿，原草稿保留。没有点击发送、Enter、submit、隐藏网络发送等路径。草稿消失只记 `left_draft`，不宣称已送达模型。
- Web 内部压缩无法观察；需要时使用“重新连接当前对话”重附稳定背景，不能把定时检查伪装为真实压缩生命周期。

停用自动捕获/自动召回各自暂停对应路径；撤销连接阻止后续本机读取和捕获，缓存结果也不能通过重复 request_id 绕过授权版本。扩展尝试移除仍能安全识别的自有草稿块，不覆盖用户编辑。已经交给网站或宿主的资料无法从对方历史中追回。

## Agent 路径

Claude Code 的 `SessionStart` 支持本项目已有的 `startup/resume/compact/clear`。可信启动参数固定连接 ID 和范围硬上限；Hook 输入的路径、scope、command、connection_id、权限字段均不能改变它们。稳定背景与动态生命周期身份分开。MCP 各次工具调用按当前连接授权重新读取，模型仍只有四种只读工具。

当前官方还提供 `fork` 以及其他 Hook，本版不假装全部覆盖。2026-10-08 核对的官方文档：

- [SessionStart 及 source 含义](https://code.claude.com/docs/en/hooks#sessionstart)
- [command 与 args 直接执行形式](https://code.claude.com/docs/en/hooks#command-hook-fields)
- [Chrome Native Messaging 的扩展来源与帧限制](https://developer.chrome.com/docs/extensions/develop/concepts/native-messaging)

示例需要用户审阅并合并到已有宿主配置；不能覆盖现有配置，不默认新增 Proxy/SaaS/团队服务器。修改宿主持久接入、实际服务账号和凭据仍由用户完成。

## 真实观察，不用单一绿色状态代替结果

`last_handshake_at` 只证明原生桥返回；`last_bootstrap_at` 只证明启动资料生成并返回；`last_read_at` 只证明读取调用成功；`last_capture_at` 只证明捕获落盘成功。它们不是模型采用证明，也不是 embedding 或后台整理已完成证明。失败保存脱敏的固定说明，具体时间让用户看出停滞；不知道的总数或缺口不能编造。

合成测试分别用于验证连接权限/撤权、实际 RecallCard Native 分帧、生命周期 JSON、Node worker 自动路径和 Chromium DOM 行为。Chromium fixture 使用自建页面和固定响应，不等于厂商 DOM、真实账号、扩展商店安装或 Agent 模型理解验收。云端环境的 Chromium socket 权限受限时使用已授权 CI，不以其他路线绕过。

旧版仅由固定 `--scope` 授权的 Agent/MCP 配置不属于新的连接记录；应由用户审阅后替换成带 `--connection-id` 的配置并停用旧入口。连接页的撤销不能冒充已经关闭所有独立旧进程或撤回宿主历史。浏览器受管理安装绝不退回旧的宽范围授权。
