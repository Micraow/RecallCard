# 独立 SQLite 普通对话词法通道

本批在同一来源版本上并行取词法和语义候选，再核对正本。它解决的工程缺口是：精确编号不能只能在 semantic top100 内重排。它不保证所有编号、同义问题或无关问题都会得到正确答案，也没有新的真实模型质量数据。

## 索引与读取

- 仅显式刷新普通对话索引时建立词法代次。版本为 `recallcard.lexical/ascii-id-cjk-bigram/1`，包含在 generation ID 中。旧库仍可只做语义查询，覆盖显示 `legacy_unavailable`；读取不会隐式建词项表或重新编码语料。
- 在已有短批处理中生成区分大小写的完整 ASCII 标识及汉字双字组，独立单字另记。标识保留 `_-. /:+#` 中的非空格符号，无前缀匹配、领域词典或问题特判表。词项哈希不构成加密。
- 每块最多各取 256 字节真实相邻正文来识别跨块词，不额外送入 embedding，也不落明文词项。完整词项上限 128 字节；较长正文 token 不会被切成短编号。派生表保留来源、块与完整匹配词项的原文字节范围和 hash。
- 词项/块/来源代次同事务发布和清理；修订、抑制、删除、撤销或范围变化仍按既有当前来源及配置校验拒绝旧结果。向量缓存与词法派生独立，显式升级可复用未变化向量。

## 两路候选和证据

1. 从倒排词项独立取最多 100 个 Event，不以语义前 100 个为过滤条件。不同查询词项的命中数量排序，非 BM25、概率或相关性分数。
2. 语义路线仍取最多 100 个 Event 的最佳 cosine 块。最多 200 个来源的并集用 `1/(60+rank)` 相加融合，之后才施加请求数量与响应预算。词法同命中数使用 competition 并列排名（1、1、3），不把 ref 字典序变成额外融合权重；语义排名不变，fusion 标识为 `rrf/2:k=60:lexical-competition`。候选读取窗口仍有上限，窗口访问次序不是完整召回保证。
3. 命中词法时主块优先使用词法块，否则用最佳语义块。语义路线可用时 `score` 为主块对应向量的 cosine；`retrieval.semantic_evidence` 独立保存最佳语义块的范围、hash 和 cosine。`semantic_rank=null` 表示未进入语义前 100，不能伪装成语义命中。
4. Rust 重新从当前 Event 验证两种证据的原文/hash/范围。词法证据还必须是当前查询中的合法完整词项；一致篡改派生 hash 也不能把 `E_PIPE_710` 的前缀认证为 `E_PIPE_71`。单个证据只证明一个查询词项，不认证所有计数或事实相关性。
5. 词法预览围绕完整证据取最多 2,048 字节，保留原始 embedding 块作为独立元数据。共享来源定位符从实际预览起点读取同一 Event。现有完整精确锚点优先层和跨 scope 稳定轮询继续保留，不比较跨模型 cosine。

结果仍为 `relevance=unassessed`；出现词项不保证能回答，更不能把助手文本、历史安排、否定或后续纠正直接升为当前用户事实。无关负例仍可能返回语义候选。

## 预算与退化

- 查询最多 32 个不同词项、块最多 4,096 项、代次最多 2,000,000 postings。
- 词法候选读取最多 8,192 postings、保留 1,024 个 chunk、100 个 Event。多个查询词项轮询读取，避免一个高频词完全耗尽后续词项的访问机会；这仍不保证预算内找全稀有来源。
- 超长词项或过多查询词项仅禁用本次词法通道，显示 `limited_query` 和固定原因码。完整原问题仍发到已批准的本机编码服务，不截断或改写。没有受支持词类显示 `unsupported_query`。损坏索引等错误仍拒绝。
- 新代次的 hybrid 查询在本机编码服务不可连接、超时或返回非成功状态时，显式降为 `fusion=lexical_only`。仍需已有完整词法代次及查询批准，不会为旧库隐式重建。已缓存且合法的问题向量仍优先用于双路检索。
- 降级不伪造向量、cosine 或语义命中：`score=null`、`score_kind=unavailable`、语义排名及证据为 null，`semantic.status=unavailable`，固定 `reason` 说明失败。`local_event_semantic=false`；共享入口按范围显示 `degraded`，有候选仍为 `partial`，没有候选为 `unavailable`。多范围中任一路语义可用时，汇总字段为 true，单路状态仍分别保留。
- 本机问题编码 HTTP 超时为 5 秒，给共享入口既有 15 秒总预算中的词法读取及正本核验留出余量；不自动重试或云回退。总预算耗尽仍可能拒绝本次查询，不承诺任意规模下必有降级结果。服务恢复后的新查询自动回到双路；失败不写查询向量缓存。
- 只有 `local_provider_unavailable` 与 `local_provider_error` 可降级。重定向、损坏响应/向量、索引损坏、预算、范围及批准错误仍拒绝；提供器等待后重验固定配置及代次。`semantic_only` 请求仍拒绝编码失败，不悄悄改变请求路线。
- 8,192 仅为倒排候选读取预算，不是完整查询工作量上限。查询前后仍按代次重验全词项 manifest，仍分页验证现有向量与块关系（降级时不算 cosine）；正本候选读取仍可能重复扫描 Event segment。内存有界不等于常量时间，大库延迟未验。
- 权限过滤、源 epoch/hash 校验、最终 8KiB 来源包和既有超时/核验预算不变。额外证据元数据也占响应字节，可能减少一次显示的候选数。所有状态经共享入口透传给桌面、MCP 和文本接力，界面提示旧索引、词法受限及截断。

## 验收边界

当前使用原创合成资料与固定 numeric/fake encoder。Python 真实 SQLite 测试覆盖语义第 101 名外编号、近邻误匹配、ASCII/汉字跨块、旧库升级与复用向量、权限范围、修订/撤回/GC、损坏索引、实际 SQLite 磁盘上限、查询/候选预算及长中文问题退化。新增编码器故障测试覆盖单路证据、恢复与缓存、错误白名单、配置/代次竞态及空/受限问题；Rust 真实回环合成提供器关闭后仍检查完整来源片段、hash、跨入口定位及撤权，最终结果以对应提交的 CI 收据为准。

真实 BGE 数据仍是 [ed7fc4 固定基线](validation/real-encoder-ed7fc4.md)，不能套用为本批混合路线改善结果。先前 [1baa2f WIP 检查点](validation/sqlite-lexical-checkpoint.md) 保留未完成和未验收状态；后续修改不倒填旧收据。
