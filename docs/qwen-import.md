# Qwen 官方历史导入

导入命令支持 `recallcard import history.json --format qwen --scope personal`，也可用 `qwen-export` 或自动识别。当前识别官方 `success / request_id / data` 包装，以及其中的会话对象、会话数组。平台保留为 `qwen`，不会伪装成 ChatGPT。

若导出是 `.part000` 等连续字节分片，目前需要先按编号合并成完整 JSON。导入器不会把每个分片当成独立会话，不会根据缺失片段猜补内容；暂不支持在文件选择器里自动重组分片。原始文件应保留，合并后先确认 JSON 完整。仅凭扩展名不能确定其他版本的分片格式。

## 来源和分层

- `chat.history.messages` 是唯一正本；`chat.messages` 是当前路径的重复投影，逐条校验后去重，不导入两遍。
- 保留全部导出的分支；`currentId` 用于标记当时当前路径，不删除其他分支，也不把兄弟节点接成连续对话。
- 用户正文来自 `content`；助手正文只取 `content_list` 中角色明确为 `assistant` 的 `answer` 段，按原段顺序连接。工具角色的 `answer` 也不会冒充助手。
- `think`、`thinking_summary`、`reasoning_content`、搜索和工具负载不进入证据正文。隐藏片段、不支持片段和空白节点分别计数。
- 附件只保留编号、名称、大小和有限类型元数据；不保存地址、嵌套文件载荷，也不下载外链。无正文但有附件的记录标记为 `file / external_quote`，不作为用户事实。
- 使用逐消息 Unix 秒时间；缺失保持缺失，绝不用导入时间冒充。保留账号命名空间、原会话/消息编号、父子关系、当前分支和 answer 段下标。
- 中间节点因无可见正文被省略时，保留原 parent ID，并记录最近可见祖先及跨过的省略节点数，供继续读原始分支。

每个 Event 明示部分覆盖。导入后的用户角色也可能是粘贴教程、代写材料或系统提示模板；角色只说明导出中的发言位置，不能自动推断为本人经历、永久偏好或新的执行授权。

## 校验、预算和安全

现代导入服务对包装中的 `data` 逐会话读取，整份文件大于单会话预算不会被误报为一个超大会话。完整包装、输入摘要、源图和消息校验成功后才提交暂存结果；晚出现的 `success: false` 或损坏尾部不会把已暂存内容写成事实源。单会话和规范化事件仍受既有资源预算限制，不截断以求通过。旧内存兼容接口仍保留其整体输入上限。

重复字段、节点身份冲突、缺失或冲突的双向父子关系、循环、重复投影不一致、未知角色、冲突当前节点和非法时间均明确拒绝。多版本去重及修订沿用共同导入语义。Memory 不由导入自动生成；整理仍需独立 review/apply。

这不是通用凭据扫描器。导出里的可见正文可能含口令，使用者应在分享或传给模型前审查。测试中的真实文件只保存在私密试验目录；仓库仅包含原创合成 fixture。`tests/import_qwen.rs` 校验角色、全部分支、重复投影、时间、附件占位、隐藏/工具金丝雀、分段顺序、预算与暂存拒绝，以及分支交接中的隐藏规则。合成协议通过不等于真实桌面窗口验收，也不等于模型整理质量通过。
