# RecallCard 0.6 开发候选版

从一份旧聊天开始。解压运行包，在其中运行 `./运行桌面版.sh`。点击「导入聊天记录」，选择 ChatGPT 或 DeepSeek 的官方 JSON / ZIP 导出。程序会在本机准备资料库，直接处理整份导出；关闭窗口或暂停后，已保存的资料仍然保留。

导入完成后，首页先展示有出处的原话。点开一条内容，可以回到原对话、查看原始时间和可用的附件说明。原话没有被包装成已经确认的长期记忆；导出没有包含的附件正文或工具结果会明确标出。

情况变化时，可以「补充最新情况」。补充会作为一条新的用户记录保存，立即可检索；原来的聊天仍然可读。它不会偷偷改写旧事实，也不需要先配置模型。

「连接 ChatGPT」准备本机读取组件的连接说明。安装或显示配置不代表 ChatGPT 已经连接，只有真实读取成功才会更新连接状态。ChatGPT 的原生 MCP 接入还需要受支持的宿主与授权；本机程序不会把资料自行上传到临时开发电脑或公共服务器。连接以后，按问题检索和读取出处，不依赖手工粘贴整段聊天。

## 资料与版本

- 这是 0.6.0-dev 开发候选版。界面内显示实际构建版本和提交。
- 来源、补充和已确认记忆都保存在所选本机资料库中。第一次升级前，复制整个资料库目录作为备份。
- 请保留运行包中的 `recallcard-desktop` 与 `recallcard`，两者必须来自同一包。连接组件缺失时，程序会给出明确提示。
- Linux 运行需要 Git、GTK 3 与 WebKitGTK 4.1。可选后台模型组件另需 Python；首次导入和阅读不依赖它。
- 不要把私人导出、资料库或密钥加入项目源码仓库。此开发版不会自动发布你的资料。

CLI 是同一资料库的独立入口。终端从包内的 `./recallcard --help` 开始；完整的导入、检索、续读、出处和 MCP 用法见 [CLI 与 AI 读取指南](cli-ai-v0.6.md)。可选模型 worker 使用随包的 `python/` 源码，需要 Python 3.10 或更新版本。

## 升级前保存完整资料

1. 暂停导入并等待当前批次保存，停止后台服务，再退出相关 RecallCard、CLI、MCP 和浏览器连接进程。备份时保持资料不再被写入。
2. 复制整个实际资料库，包括隐藏的 `.git`、events、memories、control 和 objects。默认位置为 `${XDG_DATA_HOME:-$HOME/.local/share}/app.recallcard.desktop/vault`，自选资料库按实际位置备份。
3. 同时保存该应用目录中的设置（含 `recent-workspace.json`），以及实际状态目录中的 `recallcard/`。设置了 `RECALLCARD_STATE_DIR` 时使用该目录；否则 Linux 通常为 `${XDG_STATE_HOME:-$HOME/.local/state}`。导入暂存、任务、后台配置和连接授权在状态目录，单独复制 Vault 不包含它们。系统钥匙串里的密钥不在源码包或这些备份中；会话密钥随服务退出而失效。
4. 将新版解压到独立目录，保留旧程序，先打开原资料核对来源、范围和近况。避免两个版本同时写入同一资料库。资料搬家或恢复副本可能使路径、文件身份绑定失效，任务与连接需要重新核验。

若需要回退，先停止所有相关进程并另存当前资料，在隔离副本检查升级前的完整备份，再按需一起恢复 Vault、应用设置和状态目录。旧程序读取新版写入资料尚未完成兼容验收，不能只换回旧程序就当作安全回退。原客户端可能仍使用之前复制的 CLI，换包不会自动更新这些连接。
