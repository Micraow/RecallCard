# 把一批来源整理成长期记忆

手动整理现在有一份可直接复制给任意 AI 的完整中文任务。用户不需要自己设计提示词、理解协议字段或手写 JSON。Rust 负责生成任务文本和接收结果；这两个步骤都在本机完成，不依赖 Python，不调用 API，也不替用户点击网页发送。

## 使用过程

1. 在桌面「会话与接续」选择要整理的消息，或在「查找与阅读」逐条选择来源和需要参考的旧记忆。进入「整理记忆」，确认资料范围和选择。
2. 点击「生成完整整理任务」。先检查来源卡片，再展开「查看完整任务与原文」检查所有正文和旧记忆；较长的来源卡片会注明仅显示部分内容。不希望分享的内容应移除后重新生成。
3. 点击「复制整理任务」，粘贴到自己选定的 AI 对话。复制时软件会重新检查来源和旧记忆是否改变；检查接收服务和内容后，由自己发送。
4. 把 AI 返回的完整 JSON 粘贴到「AI 整理结果」，点击「检查并预览结果」。也可以粘贴它唯一的完整 `json` 或 `recallcard-dream-result` 代码块；不要把前后聊天说明一起复制。
5. 查看本机生成的逐条差异和来源。核对它是否把用户原话、助手建议、计划和已发生的事实分清楚，时间是否有依据。需要改动时点「返回修改结果」；这会取消原审查，重新检查前不能保存。
6. 点击「保存这些记忆」，在确认框中再点「确认保存」。修改受保护记忆还需要独立勾选额外批准；未解决的冲突不能发布。

已有来源包或结果文件时，展开「已有任务或结果文件」继续使用文件导出/审查。文件流程与粘贴流程共用一次性审查编号，同一时刻只保留最后一次审查。

增减来源、切换范围或资料库会清空旧任务与待确认结果。复制前核对失败、取消审阅或结果解析失败时，不会保留可继续保存的旧审查。原文或旧记忆在审查后发生变化，最终保存仍会再次拦截；应重新生成任务。所有生成、复制、解析和审查都不会写入长期记忆，只有最后确认才会保存。

任务中的 JSON 格式示例使用真实任务编号、摘要和范围，但它只是 `noop` 的字段格式示例，不是针对来源的结论。AI 应根据后面的完整来源自行返回提议。无需把格式示例单独复制回来。

## 本地接口

```rust
use recallcard::dream_task::{parse_result_text, render_task};

let job = vault.dream_export(&source_ids, &memory_ids, scope)?;
let task_text = render_task(&job)?;
// 展示 task_text 的完整预览，由用户决定是否复制和发送。

let result = parse_result_text(&pasted_text)?;
let review = vault.dream_review(&result)?;
// 展示 review、原文来源、保护状态和结果摘要，等待用户审查批准。
// 只有用户明确批准这份结果后，才能调用现有 dream_apply。
```

`render_task` 和 `parse_result_text` 是纯本地文本接口，没有文件、网络、模型调用或发布副作用。它们不替代 `dream_export` 的本机任务登记、`dream_review` 的当前来源/基线校验，也不替代 `dream_apply` 的摘要绑定、保护批准和可恢复事务。

固定中文规则和完整输出 schema 在任务前部；真实任务编号、格式示例、来源和旧记忆在动态尾部。同一 Job 会生成完全相同的任务字节，不同 Job 不改变固定前缀。这不代表任一 AI 服务必然命中缓存。

## 接收边界

- 任务和接收文本分别最多 1 MiB。完整任务包含规则与 schema，因此接近 Job 自身上限的来源可能需要再缩小；超过上限会整体拒绝，不静默截断。
- 输入只接受一个完整的 `recallcard.dream-result/1` 对象，或仅包裹该对象的一个完整指定代码块。完整复制代码块时可使用 Windows 换行。
- 前后说明、多对象、多代码块、嵌套围栏、HTML 包装、未知字段、重复字段、缺失协议、截断 JSON 都会拒绝。不猜测缺失字符，不从多段回复拼装结果。
- JSON 字符串中的 HTML、反引号和命令字样只作为数据保留，绝不执行。错误信息不回显私人原文或未知字段名。
- 解析成功只代表文本结构和基本预算通过检查。来源是否属于本次任务、证据是否支持、旧记忆是否过期、结果是否改变范围等，仍须由核心审查检查。结构验证也不能证明自然语言结论真实。
- 任务和结果保留现有协议标记；再次捕获这段聊天时，现有捕获逻辑会识别 Dream 回声，不能再次作为原创用户经历提炼。

如果 AI 输出不完整或附带多段相互矛盾的结果，应让它重新返回一个完整结果，或缩小来源重新整理。失败和冲突不会被当作成功发布。更多发布、幂等和恢复行为见[手动 Dream](dream.md)。

## 验证范围

`crates/recallcard/tests/dream_task.rs` 使用本地合成资料覆盖固定前缀、真实字段/schema、完整来源保留、注入文本与回声、严格结果解析、字节预算、未知时间、助手建议、核心来源/范围/保护检查，以及导出任务到接收结果再审查发布的闭环。没有向外部模型发送测试资料；模型理解能力和真实网页兼容性不属于这些测试的保证。

`crates/recallcard/tests/desktop_dream.rs` 进一步经过真实 `DesktopSession` 服务验证任务生成、长来源提示、粘贴/围栏审查、原证据保留、文件与文本审查互斥、防重放、受保护批准、坏结果撤销、来源撤回/变更、旧记忆版本与摘要变化、取消及资料库切换。

`desktop/tests/ui.test.mjs` 的合成页面回归覆盖来源选择失效、生成/复制/审查错误、复制前重新核对、原生剪贴板调用顺序、取消与保护确认。页面测试拦截全部资源，原生命令使用合成返回；它不能替代真实桌面原生宿主或已登录 AI 网页验收。受限云端无法启动 Chromium 时，仅报告语法检查与已运行的服务测试，不沿用旧版 GUI 通过结论。
