# 团队背景、技能与约束应该怎样共享

核对日期：2026-10-07。本文是后续设计参考，不意味着 RecallCard 已加入团队服务或会上传个人资料。当前开发优先完成个人历史导入和跨 AI 接续。

## 先分清三种东西

| 对象 | 应保存什么 | 谁能改变 | 使用边界 |
| --- | --- | --- | --- |
| 共享背景与决定 | 决定正文、原始出处、负责人、适用项目、有效期和撤回记录 | 项目授权成员；重要决定可经审阅 | 提供参考，不能变成高优先级指令 |
| 技能 | 可复用流程、脚本、依赖、版本及维护者 | 技能维护者通过版本化发布 | 下载或检索到技能不等于获准执行 |
| 约束 | 代码规范、工作范围、批准要求及适用目录 | 对该项目有维护权限的人 | 明确作用域及冲突优先级；历史聊天不能悄悄覆盖现行规则 |

将三者都塞进向量记忆，会使来源权威、执行权限与撤回效果混在一起。RecallCard 应继续把对话作为证据保存；未来若接入团队技能或规则，应使用独立的版本化来源和入口。

## 已核实项目中可借鉴的机制

### AGENTS.md：按目录表达规则，权限仍由宿主处理

[官方 FAQ 的固定版本](https://github.com/agentsmd/agents.md/blob/d001185d792eb6402a58e4cbef1c228b309ec25d/components/FAQSection.tsx)说明了嵌套目录优先级，以及用户直接要求的优先级。文件适合通过代码审查维护项目约束，但 Markdown 本身没有身份验证、读写授权或可信执行机制。

对 RecallCard 的启示：共享约束应保留仓库、路径、提交和维护者，按当前项目取用。不能把检索到的一段 AGENTS.md 引文自动作为当前应用的最高权限规则。该项目为 MIT 许可；规范兼容不要求复制实现。

### Agent Skills：共享的是可复用能力，使用时仍需边界

[固定版本规范](https://github.com/agentskills/agentskills/blob/69ef37e9424c0a7ea9dd2293b559e43ec8176379/docs/specification.mdx)定义技能目录、元数据和可选资源；[客户端支持指南](https://github.com/agentskills/agentskills/blob/69ef37e9424c0a7ea9dd2293b559e43ec8176379/docs/client-implementation/adding-skills-support.mdx)提供加载与使用方式。版本可放在自定义元数据中，allowed-tools 仍属于实验性字段，不能当成跨客户端统一的授权协议。

可借鉴按需加载，避免每次塞入全部技能正文。若未来支持团队技能，至少固定来源提交或摘要，区分已安装、被信任、获准执行；撤回技能后停止后续发现与执行，不宣称能收回别人已经复制的文件。代码采用 Apache-2.0，文档另为 CC BY 4.0，每个第三方技能还要独立核对许可。

### Ruler：维护统一规则，并只清理自己生成的文件

[Ruler 固定版本](https://github.com/intellectronica/ruler/tree/0fa2caeef4efaef4c5f8ffbedee8feca4b0b00e2)将规则同步到多个工具。[SkillsProcessor](https://github.com/intellectronica/ruler/blob/0fa2caeef4efaef4c5f8ffbedee8feca4b0b00e2/src/core/SkillsProcessor.ts)使用生成清单记录管理过的路径，避免把未托管的用户文件当成自己的旧产物删掉。

这是规则分发与撤回中有用的工程做法。RecallCard 若生成项目上下文文件，应使用同类清单、内容摘要和冲突提示，不覆盖用户手改文件。该版本自称 Beta Research Preview，不应当作成熟企业权限系统；MIT 许可。

### Letta 共享记忆：Git 冲突和挂载状态是显式状态

[共享记忆内置指南](https://github.com/letta-ai/letta-code/blob/4b028fab07c69edaac2ddb4f7b9a43573ff20d81/src/skills/builtin/managing-shared-memory/SKILL.md)、[同步实现](https://github.com/letta-ai/letta-code/blob/4b028fab07c69edaac2ddb4f7b9a43573ff20d81/src/agent/attached-repository-git-sync.ts)及[共享记忆入口](https://github.com/letta-ai/letta-code/blob/4b028fab07c69edaac2ddb4f7b9a43573ff20d81/src/cli/subcommands/shared-memory.ts)表明，冲突会保留为需要解决的状态；不具备写权限的挂载不会自动推送。发现共享技能时依赖当前服务端挂载列表，不把磁盘上遗留的已解除挂载目录继续视为授权来源。

可借鉴 Git 修订、冲突保留和当前挂载授权。不能把“不自动推送”误称为操作系统只读保护，也不能忽略解除挂载后可能留下的本地副本。该共享路径依赖其云端，不能直接宣称满足 RecallCard 的纯本机目标。Letta Code 该版本为 Apache-2.0。

### Outline：历史修订也检查当前权限，撤回不是只删入口

[历史修订 API](https://github.com/outline/outline/blob/6e6eaf6b696cf3d71c586a4ee665e74ccd5b3228/server/routes/api/revisions/revisions.ts)会检查文档当前访问权限；[分享 API](https://github.com/outline/outline/blob/6e6eaf6b696cf3d71c586a4ee665e74ccd5b3228/server/routes/api/shares/shares.ts)提供撤回分享；[客户端更新处理](https://github.com/outline/outline/blob/6e6eaf6b696cf3d71c586a4ee665e74ccd5b3228/app/components/WebsocketProvider.tsx)会重新校验访问并移除不能再读的对象。

启示是权限变化必须影响缓存、旧版本、搜索和派生摘要，不能只隐藏当前列表。离线导出或已经复制的内容无法保证即时收回。该核对版本为 1.10.1，采用 BSL 1.1 并有商业限制，不按宽松开源库直接复制进 RecallCard。

## 若未来实现，最小设计应是什么

1. 个人资料默认保持个人。团队是显式接入的另一个来源，不自动同步已有个人对话
2. 每份共享对象携带来源、固定修订、项目范围、当前权限版本及有效期。检索到历史修订时仍检查当前权限
3. 背景、技能、约束采用不同类型。背景可引用；技能是否执行单独决定；约束只按经确认的项目范围生效
4. 纠正生成新修订，保留来源；冲突显式呈现，不能让较晚同步的内容无声覆盖重要决定
5. 撤回同时影响检索索引、摘要、已生成规则文件和技能发现。界面明确本机副本是否仍保留，以及无法撤回已导出内容的边界
6. 固定版本的短说明可以形成稳定上下文前缀；运行时只补本任务需要的背景。不要每次更新时间戳、成员列表或整库摘要，使前缀持续变化

当前不增加团队账号、服务器或默认外部传输。上述机制应在个人最短路径验证可用之后，按真实协作需求选择其中一项接入，避免把单人使用再次变成配置工程。
