# 简洁文本接力：阶段实现

当前仅有共用短语义定义和纯语法解析器，尚未接入网页、桌面或 MCP initialize，不能作为完整工具接力使用。现有 v1 入口保持原行为。

`crates/recallcard/src/recall-capabilities.json` 是短语义正本，运行 `python3 scripts/sync_recall_protocol.py` 生成扩展顶层模块，`--check` 核对同步。顶层 JS 可随既有扩展打包规则分发，桌面随后复用同一模块。

帧第一行是插件提供的 `RECALLCARD/2 T_` 加 16 个 Base64URL 字符；第二行只有 search/query、fetch/id 或 final 的严格 JSON；末行固定 `END RECALLCARD`。检索动作无正文；final 后空一行写 Markdown 正文。票据仅关联轮次，不能授予读取或外发权限。

解析器只接受一条完整原文，不修剪行首、不剥离引用或围栏、不修补 JSON、不从正文提取协议。Web query 最多 2048 UTF-8 字节，动作帧 4 KiB，final 64 KiB；核心 MCP query 仍为 4096 字节。超限拒绝，不截断执行。

语法通过仍不允许读取或提示完成。下一阶段须在宿主接入：当前问题/会话及范围绑定、前包完整发送回执、票据单次消费、只读 allowlist、来源 S/P 注册与当前权限复核、有限次数/字节/超时、取消与重试、final 一次提醒。只有本轮已核验且已发送来源才能引用。当前核心正文可通过 next_id 续读，搜索列表没有续页时不能造 P；fetch 默认读取定位符绑定的命中起点片段，不承诺从原文开头开始。

支持站点 Web 插件的整轮识别、多轮检索、正式回答提醒是本批产品目标；桌面手动复制/粘贴是跨平台回退。两者均保持人工最终发送、保护已有草稿和全文核验。合成协议测试不代表真实网页账号或模型选工具能力已验收。
