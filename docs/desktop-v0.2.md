# RecallCard 桌面版 0.2：从一个 AI 接到另一个 AI

这一版首先接通“保存会话 → 找到原话 → 换客户端继续”。长期整理、记忆维护和同步仍按后续阶段推进，不能因为安装包能运行就称整份原设计已经完成。

## 从网页带入当前对话

1. 在桌面创建或打开资料库，进入「连接与状态」，选择允许使用的资料范围
2. 正常安装 0.3 浏览器扩展，填入扩展 ID 和浏览器；需要直接保存时勾选「允许保存预览确认的对话」，在原生窗口确认。Linux 支持 Chrome、Chromium、Brave；已有 RecallCard 注册会备份后更新
3. 回到 DeepSeek / ChatGPT 网页，打开扩展，点击「检查连接」。只有扩展显示当前资料库后，才算浏览器实际连接成功
4. 点击「读取当前可见会话」，检查角色、原时间和消息选择。点击本机保存预览，再确认保存；原始时间读不到就显示未知，不把捕获时间当成原时间

未连接本机也可以导出 JSON 或 Markdown。桌面「添加资料」按来源选择扩展文件、ChatGPT 官方 conversations.json 或 Claude Code 日志。新笔记是本人的新补充，不能代替多角色聊天导入。

## 继续这段任务

在「会话与接续」选择一段已保存的对话，读原话，填写接下来要做什么。点「准备交接内容」，检查生成的背景、角色、原话、来源和覆盖说明，然后复制到目标 AI；最终发送由自己完成。

交接只带有界的最近消息，不能宣称目标 AI 已收到未发送内容。没有做过整理也能使用已保存 Event。需要自动按需检索的本地客户端，可在「连接与状态」生成 MCP 配置：软件会准备持久的本机只读组件，配置加入宿主后以 bootstrap 和一句已保存原话检索验证。生成配置不等于真实宿主已经接通。

## 保存与读取分别授权

MCP 始终只有 bootstrap/search/read/sources。浏览器用户界面的 connection/capture_preview/capture_save 是独立通道，固定本机 capture_scope；模型 action 不能取得写入权限。更改选择或内容必须重新预览。保存遇到中断可重试同一快照，已写入来源版本会去重。

可见会话始终标为部分覆盖，不自动滚动，不读网络、登录令牌、隐藏推理和私有 API。无法判断角色时在扩展预览中确认。没有稳定网站消息ID时采用捕获内ID，明确不承诺跨次新捕获的绝对去重。

## 当前验收边界

本机新增回归覆盖实际扩展交换文件 → 真实 Native 安装副本 → 保存 → 原文搜索，并验证角色、未知时间、独立写许可、范围和重复保存。桌面会话、交接和取消/切换权限已有本地测试。真实 Tauri/Chromium 的本阶段结果以对应验证运行记录为准，不沿用 0.1 的通过结论。

云桌面受管理浏览器仍禁止加载扩展，未绕过。合成 DOM / Native 子进程不能证明真实登录态网站与已安装扩展完整联通。DeepSeek 页面结构的证据及当前限制见 [扩展使用说明](browser-conversations-v0.3.md)。
