# 有界候选重排：实现范围与验收

本批在现有本机 Event 向量候选中补上可解释的精确锚点优先，并在桌面选择资料时显示候选支持说明。它没有增加独立词法召回、模型或云回退，也没有得到新的真实模型命中率结果。

## 行为

- Python 仍只返回最多 100 个 Event 的最佳语义块。Rust 先核对当前权限、原文 hash、快照、UTF-8 range，再检查实际返回的最多 2,048 字节片段。
- 完整、区分大小写的代码样式标识、闭合引号内容，或整个查询就是一个 ASCII token 时，可以进入优先层。普通英文句子的单词只记录字面支持，不作为必须命中的代码标识；没有词典或问题特判表。
- 标识 token 包含字母、数字及 `_-. /:+#`（空格只是此处排版，不属于 token）。`v2.4` 不匹配 `v2.4.1`；`rg` 不匹配 `cargo`；`C++` 不匹配 `C`。标点连写也可能保守地不匹配，候选仍保留在语义层。
- scope 内先保护层后语义层，各层保留原排序；外层先轮询所有 scope 和 Memory 的保护层，再轮询其余候选。原 cosine 保持不变，并分开记录 semantic_rank、scope_rank、final_rank。
- 所有候选仍为 relevance=unassessed。来源里出现了标识，不代表能回答问题，更不证明否定、历史安排、后续纠正或助手建议是当前用户事实。

## 覆盖与资源边界

- 这是候选窗口内的重排。它无法找回 semantic top100 外的 Event，也不会搜索同一 Event 中没被选为最佳语义块的其他段落。`match_scope=returned_excerpt`，未匹配不能推断整个 Event 不含该标识。Event 使用原文相邻字符确认片段两端是否截断 token；Memory 片段无法看到相邻字符时，触边 token 保守不保护，避免将 E_PIPE_710 截成 E_PIPE_71。
- 在来源核验之间检查原有 deadline，累计命中候选 Event 的正文达到 32 MiB 后不再开始下一条。单次来源读取可以跨过该累计门槛；candidate_text_bytes 只统计命中 Event 的正文，不包括同一 segment 中其他记录的重复扫描，不是实际磁盘 I/O 字节或操作系统级时间／内存硬限制。无保护锚点或核对受限时，不扩大原有候选验证窗口。
- 候选先核验和重排，随后才应用 scope 内 20 条／24 KiB、外层 10 条／8 KiB 预算。所有计数和期限截断如实保留。
- 问题超过 2,048 字节或 64 个 ASCII token 时跳过新增锚点核对，显示 limited，并保留语义顺序。不会因此丢弃来源或扩大权限。
- 检索到候选不等于存在答案。本批没有加入任意 cosine 阈值、没有把无关负例伪报成“已解决”，也没有给纯语义候选赋予相关性置信度。

## 验收与后续

新增纯策略反例涵盖编号／版本邻居、大小写、短词边界、路径与操作符、普通英文、引号、否定／纠正／助手文本、超长查询。Rust 应用链夹具专门让正确标识落在语义第 26 名，检验它在输出截断前获得优先，并保留原 cosine 和 unassessed 状态；该夹具使用固定 fake encoder，只能验证工程行为。外层单测检查跨 scope 优先、公平同层顺序和总数限制。

真实 BGE 首次基线仍见 `validation/real-encoder-ed7fc4.md`。本批测试结果以对应提交的 CI 为准，不能套用旧提交的绿色状态；文档也不代表已通过新增 Rust 应用链或真实模型评测。

真正混合召回的下一阶段应将独立词项作为同一 SQLite 索引的可重建派生通道，在已有短批导入时生成；词项版本、代次、删除／修订／撤权同步、磁盘预算和切块边界都必须有明确合同。不能常规调用旧的全库正文加载来冒充有界索引，不能把低熵词项 hash 宣传成加密。需要固定新的独立正／负例与冲突集，再比较两路召回和融合结果。
