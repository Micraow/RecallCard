# 项目级 Codex / Claude Code 接入

这条入口把固定本机 RecallCard 程序、一个项目目录和一个明确读取范围写入宿主支持的项目配置。它不启动 Codex、Claude Code 或模型，不写入用户全局配置，也不获取宿主账号凭据。

## 预览与应用

应用层提供 `agent_install::plan(vault, request)`、`get_plan(vault, plan_id)`、`apply(vault, plan_id)` 和只读 `inspect(vault, connection_id)`。CLI 与桌面必须从同一安装的可信程序位置填入 `binary_path`；这里的路径及摘要校验只固定选中的程序，不能证明任意用户提供的可执行文件来自 RecallCard。

`InstallRequest` 明确包含 `client`、`scope`、`project_dir`、`binary_path`。`connection_id` 留空时，由客户端与规范项目路径确定项目专属的连接；提供编号时必须与该项目身份一致。不同项目分别授权、分别撤销。

1. 预览不创建连接授权，也不写项目配置。它只在项目、资料库以外的本机状态目录保存有界计划。
2. 预览返回准确目标路径、原文件摘要、结果摘要、RecallCard 管理的增量和拟授权范围。原配置全文及其他服务凭据不会进入公开结果。
3. 首次应用是用户对该计划的确认。应用先完成配置、清单与恢复日志的持久化，最后才创建所展示的只读连接授权。已存在的授权必须允许该客户端读取所选范围；不会悄悄扩展授权。
4. 计划有效期为 30 分钟。文件、程序内容、管理记录或授权版本变化后拒绝旧计划，要求重新预览。已开始的同一事务可以继续恢复。

Codex 写入 `.codex/config.toml` 的一个独立 `[mcp_servers.recallcard_…]` 配置，以及 `AGENTS.md` 的受管理段落。TOML 保留其他设置与注释；不接管同名的外部 MCP 配置。

Claude Code 写入 `.mcp.json` 的一个独立 `mcpServers` 条目和 `CLAUDE.md` 的受管理段落。在 Unix 平台还添加 `.claude/settings.json` 的 `SessionStart` Hook，覆盖 `startup`、`resume`、`compact`、`clear`、`fork`。JSON 保留其他字段与已有 Hook，必要时重新排版。Windows 版本不安装尚未验证 shell 兼容性的 Hook，预览中明确提示。

受管理段落要求新会话、恢复及压缩后主动调用固定程序的 `--json connection-context ID --scope SCOPE --budget-bytes 4096`，再读取结果指定的 `file_path`，以有限背景和原始会话目录作为首层。涉及既有偏好、决定或历史时，通过同一已授权 MCP 深入检索。宿主禁止执行本机只读命令时可用 MCP `bootstrap`，但明确告知它与文件入口的目录覆盖可能不同。静态指引不保存个人事实；每次读取重新核验授权，被拒绝时不得改为直接读取资料库。

## 冲突与恢复

每个配置文件限制为 256 KiB，最多保留 32 个待处理计划。计划及恢复日志保存在私有本机状态目录，Unix 目录权限为 `0700`，新日志文件为 `0600`，不进入项目仓库或事实源。

应用持有安装事务锁；已有连接同时持有授权锁。每个新文件先在受保护的本机恢复目录暂存并同步；即使进程中断，包含原配置全文的临时文件也不会留在项目中。替换已有配置时，先将当前实际文件原子移入受保护的恢复目录，核验移出文件的真实摘要，再以不覆盖已存在目标的方式发布新文件。若编辑器在暂存期间改写，或在移出后新建目标，保留用户内容并停止。旧文件描述符之后的写入仍留在所保留的实际 inode 中。

恢复目录位于项目和资料库以外，Unix 目录权限为 `0700`，备份文件为 `0600`。项目与恢复目录必须位于同一文件系统；跨磁盘时安全拒绝，不降级为复制覆盖。成功结果提供 `backup_paths`；这些恢复文件保留，不自动删除。

多文件中途失败会尝试恢复本次修改；一处用户并发编辑不会阻止其他未被外部修改的文件恢复。实际原文件及回滚移出的文件保留在恢复目录，不以预览时的旧副本覆盖用户新内容。首次连接此时尚未激活，已有授权不扩展。中断可重试同一计划继续或恢复；已回滚计划需要重新预览。完成标记写入失败但配置及最后的授权激活已成功时，返回实际成功并提示恢复完成标记，不将既成成功虚报为失败。

符号链接、Unix 硬链接、父目录跳转、主目录或文件系统根目录作为项目、外部同名配置、手改的受管理段落、超限和无效格式均拒绝。Claude 路径不接受 `${…}`，避免宿主将固定路径展开为其他位置。Unix Hook 逐参数使用单引号转义。

`inspect` 核验安装清单内的完整文件摘要及固定程序摘要。缺失、改写或程序变化返回 `configuration_changed`，不会读出配置正文；它不启动程序。即使只是其他设置变化也保守标记为变化，可重新预览确认。

## 证据边界

成功结果仅为 `configuration_written`，`host_verified` 始终为 `false`。宿主仍可能要求信任项目、批准 MCP 或 Hook。安装配置、RecallCard 本机试读成功、宿主实际发起读取是不同证据。

Linux 合成 HOME/项目测试覆盖预览隐私、保留设置、幂等应用、独立项目身份、范围变更与撤权、过期与程序变化、路径与符号链接、冲突、中断继续及恢复；普通受控回归还覆盖暂存后并发编辑、移出后新建目标、旧文件描述符写入、回滚时保留外部修改、第二文件写入失败不激活首次授权、硬链接不改变别名权限。测试不执行 Codex/Claude。真实宿主加载、macOS 和 Windows 原生行为仍需独立验证。

官方格式依据：

- [Codex MCP 配置](https://developers.openai.com/codex/mcp/)：项目 `.codex/config.toml` 与 `mcp_servers`，项目需要受信任。
- [Claude Code MCP](https://code.claude.com/docs/en/mcp)：项目 `.mcp.json`、`mcpServers` 和宿主批准行为。
- [Claude Code Hooks](https://code.claude.com/docs/en/hooks)：`SessionStart` 的 matcher、命令与生命周期输入。
