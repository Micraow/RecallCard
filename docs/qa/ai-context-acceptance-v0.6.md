# v0.6 AI 读取验收记录

2026-10-08，使用合成资料库，通过真实 CLI 和 stdio MCP 让实际模型完成问答。模型先看到问题与只读工具入口，回答后才对照预先保存的期望；没有向模型提供答案或正文偏移。

## 任务与观察

资料包含项目初始决定、失败原因、改案、后续用户纠正，一条仍为 active/protected 的旧 Memory，以及另一个资料范围内的同名项目。另有超过 32 KiB 的原始日志，关键事实位于末尾。

初版模型能找到当前方案、复核时间和负责人，按后来的用户原话识别旧 Memory 冲突。追加纠正后，它重新查询并采用新安排，没有把助手建议当成用户决定，没有把计划说成已经执行，也没有混入另一范围的信息。

但初版无法核实长日志末尾事实：搜索只给正文开头，read/sources 在最大单次预算下仍只有 pending_refs。模型明确说明无法取得，没有猜测。因此初版只能判为部分通过。

改动后，搜索返回命中附近的原文与字节定位，read/sources 提供有界续读。另一轮实际模型面对完整问题，先检索再读取日志末尾的原文区间，并核对旧 Memory 的原始证据，回答了全部指定事实。CLI 也独立完成 setup、import、search、read、sources、status，以及按定位和游标继续读取。

## 证据边界

- 证明的是这一个固定合成任务中的实际模型工具使用，不等于通用检索质量评测。
- 测试入口调用真实 CLI/MCP，不是假造模型结果；它也不等于已经在用户的 ChatGPT 宿主完成安装和授权。
- 旧 Memory 没有被测试脚本标为失效或改写。此次模型通过更新的原话判断冲突；后台自动整理是否能可靠更新它，仍需另行验证。
- 用户的真实官方存档仅在本机进行导入、检索、来源阅读和重复导入验证，未进入模型问答测试或公开仓库。

此前本机数据门禁的独立复验覆盖跨范围来源隔离、已提交计数恢复、紧凑事务日志恢复、分支来源与资源上限。本次续读继续在每一页检查权限、抑制、引用和快照，不能凭旧游标扩大访问。
