# RecallCard 0.5：带着以前的对话继续

以下说明桌面0.5的导入流程；版本与校验值以安装包内的构建信息为准。

## 第一次使用

1. 打开桌面版，点击 **开始使用**。程序会准备本机保存位置，无需先选文件夹或填写配置
2. 点击 **选择导出文件**，可同时选择多份 JSON 或 ZIP，无需解压。检查总数，点击 **导入全部**，只需确认这一次
3. 完成后点击 **查看已保存会话**。打开一段对话，点击 **带到另一个AI**，检查交接内容后复制到目标 AI，自己发送

原有资料仍可从 **打开已有资料库** 进入。需要自行指定保存位置时，再使用 **创建新资料库**。

## 获取 DeepSeek 历史

在导入页展开 **还没有导出文件？从 DeepSeek 获取全部历史**，点击 **打开 DeepSeek**。在网站里进入：头像 → 系统设置 → 数据管理 → 导出所有历史对话。等网站生成后下载，再回到 RecallCard 选择下载的文件。

网站可能提供两份文件，请一起选择。RecallCard 不把点击下载当成下载完成，也不把某个页面可见的消息当成全部账号历史。当前没有自动操作登录网站、自动触发导出或接管浏览器下载的功能。

如果文件结构不支持或损坏，会显示错误，不把读取到的一部分冒充完整导入。旧版导出和第三方转换格式仍需按实际结构验证。

## 数量多时怎么办

导入页显示已处理数，可随时 **暂停导入**。已保存内容保留，稍后点 **继续导入**；重复导入同一文件也会跳过已存在的消息。

重新打开应用后，进入导入页，点 **查看未完成的导入**。恢复使用已核对的本机快照；若快照没有准备完成或已损坏，程序会要求重新选择文件。不会自动恢复未知任务。

每批最多32个文件、100000条消息；文件体积和ZIP展开限制见[导入格式说明](deepseek-import.md)。超过上限会明确停止。

## 重新生成过回答的对话

DeepSeek 导出中的各个可见分支都保留。交接时选择要继续的末尾消息，只带上经过该分支的原话，不混入其他回答。分支很多时，可在阅读页面翻到对应末尾，再点 **从此分支继续**。

缺失的原始时间保持未知，隐藏推理和附件原件不导入。交接预览会提示省略或无法访问的消息；原始对话仍是可追溯的资料，不会因导入自动变成已确认记忆。

## 验收边界

具体通过与未运行项目见同版本验收记录及[实施状态](progress.md)。本地核心测试、模拟界面边界与真实原生窗口验证是不同层次。用户自己的 Arch/KDE Wayland、登录态 DeepSeek 官方导出以及未知旧版文件尚未实测。
