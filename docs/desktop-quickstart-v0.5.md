# RecallCard 0.5：带着以前的对话继续

以下说明桌面0.5的导入流程；版本与校验值以安装包内的构建信息为准。

## Linux 验收运行包

本批是 **0.5.0 / 12f4672** 的开发构建运行包，包含桌面程序、配套CLI、中文说明、合成示例和依赖许可证。解压到新的独立目录后运行“运行桌面版.sh”；无需覆盖旧程序或安装到系统目录。不要只移动桌面程序，连接功能需要同目录的 recallcard。

程序元数据为0.5.0；左下角遗留的“桌面版0.4”是尚未同步的显示标签。以 build-info.json 中的提交和程序摘要辨认本批，不按文件修改日期或界面标签混用版本。程序字节与[37步原生验收](https://github.com/Micraow/RecallCard/actions/runs/37707650839)核对一致，未为更改标签重新编译。

需要Linux x86_64、Git、GTK3和WebKitGTK 4.1；最低GLIBC版本见build-info.json。系统库由发行版包管理器提供，本包不自动安装依赖、不修改系统设置。Ubuntu 22.04的官方库名为[libwebkit2gtk-4.1-0](https://packages.ubuntu.com/jammy/libwebkit2gtk-4.1-0)；Arch官方包为[webkit2gtk-4.1](https://archlinux.org/packages/extra/x86_64/webkit2gtk-4.1/)，其依赖包含gtk3。用户自己的Arch/KDE Wayland尚未实测；本批标准环境是Ubuntu 22.04/X11。

终端执行方法（在解压后的目录）：

```sh
sha256sum --check SHA256SUMS
./运行桌面版.sh
```

若解压工具没有保留执行位，仅为同目录的“运行桌面版.sh”、recallcard-desktop和recallcard开启可执行权限，再启动。不要用root运行桌面程序。这里是解压运行包，不是AppImage/deb安装事务的验收声明。

## 从旧版继续与备份

1. 先暂停尚在运行的导入，确认界面已停止处理，再退出所有 RecallCard 窗口及相关 CLI、MCP、Native host、后台任务。备份过程中不要有其他进程写入资料
2. 完整复制实际资料库目录，包括隐藏的 `.git`、events、memories、control、objects 等全部内容；不要只备份导出片段。默认资料库是 `${XDG_DATA_HOME:-$HOME/.local/share}/app.recallcard.desktop/vault`，自选资料库以实际路径为准
3. 同时备份 `${XDG_DATA_HOME:-$HOME/.local/share}/app.recallcard.desktop` 中的应用设置（含 recent-workspace.json），以及实际状态目录：若设置了 RECALLCARD_STATE_DIR，使用该目录；否则通常为 `${XDG_STATE_HOME:-$HOME/.local/state}`。其 `recallcard/<资料库规范路径的摘要>/` 保存导入快照、任务和 Dream Job，不能只备份 Vault。若启动配置改过这些环境变量，按启动时的实际值备份
4. 将本包解压到新的独立目录，保留旧版程序。仅换程序时保留资料库与状态目录的原路径、访问身份及环境配置；新程序会尝试恢复已记住的资料库，没有恢复时点“打开已有资料库”。不要在已有资料上点击“创建新资料库”
5. 先核对会话、范围和最近几条原话，再开始导入。未完成导入必须明确继续；重复导入会跳过已有记录。状态与原资料库路径绑定，搬家或改名后不保证任务还能续传

本包没有删除、迁移或清空旧资料的安装脚本。不要让两个版本同时写同一资料库。旧版能否读取新版写过的资料未经兼容性验收，不能只换回旧程序就认定安全回退；需要回退时先退出所有相关进程，保留当前资料，在隔离副本中检查备份与旧程序，必要时一起恢复升级前的 Vault、应用设置及状态目录。不要直接覆盖正在使用的资料。

MCP 与浏览器连接会复制 CLI 到生成的连接目录；只换本运行包不会自动更新已连接客户端。需要更新时，在界面的连接配置中重新生成相应组件，并按可见说明更新客户端配置；不要把旧连接仍在运行当成新 CLI 已启用。

## 第一次使用

1. 打开桌面版，点击 **开始使用**。程序会准备本机保存位置，无需先选文件夹或填写配置
2. 点击 **选择导出文件**，可同时选择多份 JSON 或 ZIP，无需解压。检查总数，点击 **导入全部**，只需确认这一次
3. 完成后点击 **查看本批会话**。打开一段对话，点击 **带到另一个AI**，检查交接内容后复制到目标 AI，自己发送

原有资料仍可从 **打开已有资料库** 进入。需要自行指定保存位置时，再使用 **创建新资料库**。

## 获取 DeepSeek 历史

在导入页展开 **还没有导出文件？从 DeepSeek 获取全部历史**，点击 **打开 DeepSeek**。在网站里进入：头像 → 系统设置 → 数据管理 → 导出所有历史对话。等网站生成后下载，再回到 RecallCard 选择下载的文件。

网站可能提供两份文件，请一起选择。RecallCard 不把点击下载当成下载完成，也不把某个页面可见的消息当成全部账号历史。当前没有自动操作登录网站、自动触发导出或接管浏览器下载的功能。

如果文件结构不支持或损坏，会显示错误，不把读取到的一部分冒充完整导入。旧版导出和第三方转换格式仍需按实际结构验证。

## 数量多时怎么办

导入页显示已处理数，可随时 **暂停导入**。已保存内容保留，稍后点 **继续导入**；重复导入同一文件也会跳过已存在的消息。

重新打开应用后，进入导入页，点 **查看导入记录**。可以找回已完成批次，也可明确继续未完成任务。恢复使用已核对的本机快照；若快照没有准备完成或已损坏，程序会要求重新选择文件。不会自动恢复未知任务。

零新增的重复批次仍能查看本批已有会话，不会混入无关的最近会话。部分失败或暂停时只列出已经核实保存、目前仍可访问的成果。检索结果也可以勾选不同会话的原话，点“带走这些资料”，核对出处、角色和未知时间后再复制。

每批最多32个文件、100000条消息；文件体积和ZIP展开限制见[导入格式说明](deepseek-import.md)。超过上限会明确停止。

## 重新生成过回答的对话

DeepSeek 导出中的各个可见分支都保留。交接时选择要继续的末尾消息，只带上经过该分支的原话，不混入其他回答。分支很多时，可在阅读页面翻到对应末尾，再点 **从此分支继续**。

缺失的原始时间保持未知，隐藏推理和附件原件不导入。交接预览会提示省略或无法访问的消息；原始对话仍是可追溯的资料，不会因导入自动变成已确认记忆。
