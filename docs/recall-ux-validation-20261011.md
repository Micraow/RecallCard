# 从概览到原话：合成用户召回验收

2026-10-11，人工在本地模型网关后逐轮阅读实际输入、选择工具与回答。
调用真正的 RecallCard MCP 子进程；没有把 Memory ID 预先塞给模型，没有外部模型账号或 embedding。
合成资料覆盖三个主题、旧决定被明确替代、助手未采纳建议、发布日期冲突、未整理原话、重复导入和另一隔离范围。
这些 Memory 是审核后的测试夹具，经正常 CLI 写入，不冒称模型生成质量。

## 用户结果

1. “现在忙什么”：找出 Atlas、Cedar、阅读三条线。
2. “Atlas 当前架构”：正确区分旧的不启用 worker 与当前仅离线编码；不把助手云方案当用户决定。
3. “原来怎么说、后来怎么改”：提供两条确切用户原话与时间，复用前问已读证据，新增工具调用为 0。
4. “Cedar 发布和未整理安排”：确认发布日期未定；从尚未整理的 Event 找回小林/PDF 导出/Cedar，未混为 Atlas。相对日期换算有依据，原话未提供时区则明确未知。

重复导入新增 0 个 Event。实际工具结果没有泄露隔离标记，也没有把 superseded Memory 作为当前结果召回；历史原话仍可核验。

## 真实发现与修复

- 层级目录不能批读，原 schema 的 `refs` 上限 32 没讲清组合限制，造成一次错误。
- `compact` 或相邻导航也要求单引用，造成第二次错误。
- `sources(memory, compact)` 只返回来源引用，旧文案让人误以为小集合总有正文，增加不必要往返。
- 初始化提示强制先 search，与目录优先冲突。
- 没有旧标签时 bootstrap 写“暂无记忆分类”，但新层级目录实际存在。
- 测试 Agent 桥把 MCP 文本再次包成 JSON，产生不必要转义。现在直接转交真实文本并保留错误标记。

修复后的描述明确组合约束、目录优先与 compact 概览；原始失败保留。产品权限和原话内容没有放宽。
16 项导航回归、16 项人工网关测试、Rust fmt/全目标 Clippy 通过。源码修复为 `8a1fcbf`；现成候选 ZIP `66e9b7f` 尚未包含这次后续提示修复。

## 成本，不能只看命中的正文

基线四问：13 个模型轮次、16 次工具调用（2 次错误），累计序列化请求 391,950 UTF-8 字节。
其中重复工具 Schema 为 110,708 字节；独立工具结果合计 25,251 字节，其余主要是随对话重复发送的历史和消息封装。

仅重测第一问：

| 指标 | 原概览 | 修复后概览 |
|---|---:|---:|
| 模型轮次 | 6 | 4 |
| 工具调用 | 9 | 6 |
| 参数错误 | 1 | 0 |
| 累计请求字节 | 112,383 | 53,335 |
| 工具结果字节 | 20,028 | 6,366 |

请求字节少约 52.5%，但不是“无损节省”：原概览顺带搜索了未整理安排；优化概览只概括已整理摘要，并明确此覆盖边界。
同四个目录以充足预算比较，full 12,564 字节、compact 3,282 字节，路径引用一致；compact 本来就省略完整溯源元数据。

这些是精确序列化字节，不是实测 tokenizer token 或账单。粗略 bytes/4 代理：四问约 97,990；单概览 28,097 → 13,335。中文、JSON 转义、供应商计量与缓存都会改变真实值，不能据此报价。
固定 Schema 仍约 9 KB/请求；在这份仅八条可见 Event 的小样本中，协议开销明显，不能宣称比全量小文本更省。大库优势需另用代表性规模测试。

## 复现边界与下一步

`scripts/manual_mcp_agent.py` 支持 `--followup-questions`（字符串数组 JSON），每轮保存不可变计量文件。
人工只看该轮网关实际请求，工具必须是 MCP 真正公布的只读能力；每个最终回答才推进下一用户问题。
原始模型消息与工具 Schema 留本地，不进入验收摘要或公开仓库。

当前能真正由浅入深召回；还需要把这条路径接到正常用户会话和桌面按钮，并针对代表性大库检查目录概览与长对话历史预算。
真实 embedding 不是这轮验证的前提，外部凭据与供应商质量验收另行处理。
