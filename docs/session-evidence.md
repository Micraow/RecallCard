# 可选的会话原文组装

`search(target="events", detail="session_evidence")` 是独立验证中的简化路径。
它保留 discovery 的词法、向量两路会话顺序，以及已有 `limit` 和总 `budget_bytes`，
直接返回多个候选来源的有界上下文。排序权重、默认模式和候选规模不变；没有调用
reranker，也不把返回的来源标为答案。

## 一次取得上下文，再按需定位记录

每个来源最多保留两个不同的命中 Event：原先首路的命中，随后优先取另一路的不同
命中；两路命中相同时，取首路的下一个不同 Event。两处命中来自同一 Event 时仍只
保留一个 Event 锚点，本批不重新设计片段排序。

随后复用 `session_context` 的来源图展开：每方向最多三跳，每来源最多十二条消息。
先按 `limit` 将来源分批，在每批中轮流为各来源分配下一段原文；来源内部也先给每条
消息一个片段，再取长文本余下部分。长回答不会先占完预算而让其他来源一直排在后面。

`results` 中每段文字保持原文，附带角色、时间、原引用、字节范围、snapshot 和引出
它的锚点。`sessions` 绑定实际来源身份，保留各路排名及原始分数。不跨记录拼造引文。

各来源独立展开。某个来源图存在循环时，保留该源独立检索到的锚点原文，停止该源
图展开并标注 `source_graph_cycle`；其他来源照常处理。旧 `session_context` 的
循环错误语义保持不变。

证据足够时直接使用；不足时读取已返回的引用和范围，或在候选 `session_ref` 内
再次搜索定位。会话标签不等于身份，仍要核对实际来源组。继续保留 scope、角色和
时间过滤、`as_of`。原有 reader 负责权限、分支和原始记录边界。

`next_cursor` 只分页已经选定的窗口和后续来源批次，不扩大图窗口。继续时须保持
查询、模式、limit 和字节预算。`complete` 只表示选中的有界窗口读完，不表示整场
对话或整个档案都读完。未返回邻居也不证明邻居不存在。

## 成本与验证边界

预算包含整个返回 JSON，不只正文。丰富上下文可能减少首屏来源数；小预算仍可能
容不下第二处命中。原文覆盖、来源覆盖、总字节和调用次数应分别测量，不能把字节数
当作 token，也不能把更多文字直接称为答案质量提升。

本批测试仅使用原创合成原文和向量。已知问题的确定性回放也只能测覆盖与成本，不能
称为新盲测或泛化证据。生产默认保持原样，需独立检查与另行冻结的质量评估再决策。

## 收敛方向与可删除的旧假设

这个入口是暂时的对比边界，不是永久增加第七套调用流程。若独立检查和质量评估支持
组装路径，后续普通调用者收敛为一次搜索取得证据、必要时读取。届时修改主要工具
说明，停止扩展实验性判断证明控制器；旧模式名在明确的兼容期内作为适配入口保留，
允许迁移后删除各自的重复编排。

应淘汰的假设包括：最佳检索碎片代表整场对话；必须先选唯一来源才能定位记录；每次
检索都必须经过核查判断器和末条证明；格式验证能证明语义相关。需要保留的是权限、
来源与分支身份、原文不变和总工作量/字节预算。

验收看是否保住有用命中及前后交流、来源覆盖、总成本、调用者步骤是否更易理解，
不以防御分支或测试数量当作检索质量。
