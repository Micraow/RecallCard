# 无模型查询改写：固定集与独立留出诊断

结论：本轮不修改生产默认。通用去问句框架词、字段与意图加权没有解决无字面重叠的同义查询；单字放宽提高来源命中，同时明显增加无答案查询的候选。不能把这些规则上线后称为语义改善。

## 先分清缺候选还是排错序

原有 `short-question` 集含 12 条原创来源、52 问，其中 40 个正例、12 个无答案查询。9 个同义问题与各自预期原文的汉字双字组交集全部为空。当前自然问题入口要求完整 ASCII 标识符，并在无标识符时要求至少 3 个匹配双字组、覆盖比例和连续 3 字。因此这 9 项不是仅靠排序权重能修复的情况。

回放器从当前 `context.rs` / `context/search.rs` 原样提取 11 个生产函数，使用 `rustc` 和标准库编译，无 Cargo 重编译、模型、网络或新增 Python 包。词法扫描器仅提取唯一顶层函数，拒绝缺失、顶层重名、签名或属性漂移、残缺字面量和注释；没有失败后换成近似 Python 评分的回退。记录生产文件、逐函数、生成程序及二进制摘要。

留出集的通用 metadata_rule 允许标题检索，而当前生产投影不索引会话标题；报告保留这项能力差异，不因结果不好修改标注。

这是排名核回放，不是完整 Context/CLI/MCP：来源已按合成 scope/revoked 字段过滤，再送入真实排名函数；附件只模拟当前 UTF-8 正文和独立文件名字段，标题不会伪装成已有检索字段。同分用 fixture 的 source_id，不是实际 Event hash ref；不包含生产分块、事务、权限竞态、语义融合、来源合并和最终字节预算。空白/纯标点在诊断里记为无候选，不能据此推断完整 API 的错误回执。

## 冻结方法

- 既有 52 问属于已观察开发集，不称盲测。
- 独立留出集：24 来源（12 Event、12 attachment），64 问（42 正例、22 无答案），6 个 scope、2 条撤销来源。普通发言保留 user/assistant；附件 role 为 null。
- 留出集不根据候选结果编写。候选在首次读取该集前冻结，之后没有按结果调参数。`experiment-lock.json` 校验候选和留出文件摘要；这份留出集现在已观察，后续调参不能继续称为新的盲测。Hash 只证明内容身份，不能单独证明编写独立性或冻结先后。
- 仅显式 question 输入参与改写；exact 和引号保护保持原输入。删除框架/疑问语法时留空格，不拼出原问题不存在的新相邻词。不加入领域同义词或 9 题答案映射。
- 字段/意图只重排已经进入候选的来源：正文词项占比权重、明确时间表达或原因连接词的有限加权。它不能创造缺失的语义证据，也不宣称来源可以回答问题。
- 单字放宽是负对照，明确绕过生产双字组门槛；不进入生产或建议默认。

## 结果

表中 Top5 分母是正例查询数。“非预期候选”是全查询前五项中未列在对应 expected_sources 的累计项数；“无答案非空”分母是该集无答案查询数。标注要求可直接回答，未穷尽所有同主题相关证据；这些计数不等于生成答案错误率。

### 已观察固定集

| 方法 | 来源命中 Top5 | 同义命中 | 非预期候选 Top5 | 无答案非空 |
|---|---:|---:|---:|---:|
| 生产默认 | 22/40 | 0/9 | 1 | 1/12 |
| 生产显式问句 | 31/40 | 0/9 | 1 | 1/12 |
| 去通用问句框架 | 28/40 | 0/9 | 0 | 0/12 |
| 再加正文/意图权重 | 28/40 | 0/9 | 0 | 0/12 |

前两行复现已有实际 CLI 的来源命中总数。去框架词还可能让长句回到完整词组匹配，损失本来可找到的来源；因此不能只报“误候选减少”。

规范化的总命中不变也不代表无回归：它救回 Q01，却丢掉原本可见的 Q34；移除 Q33 的无答案候选，又在 Q53/Q54 引入新干扰。报告额外列出逐题成对变化，不仅比较总数。

留出集同义类别有 6 问，生产问句为 3/6、规范化仍为 3/6、单字负对照为 6/6；它与原 9 问不是同一难度，不能只挑这一列宣传成功。所有方法都未返回已过滤的 scope/撤销来源；这些负例仍可能匹配其他可见但无答案的来源，属于候选噪声，不应误报为权限泄漏。

## 已执行与边界

本地 42 项方法合同通过，包括生产提取/协议、实际词项与评分、空输入、完整标识符、引号、作用域先过滤、附件独立证据和字段只重排。两个独立进程分别使用 `PYTHONHASHSEED=1/2`，完整 `results.json` 逐字节一致。方法代码、固定/留出输入和冻结 hash 均保存；没有把临时 Vault、机器路径、私人资料或原始运行目录提交进仓库。

本轮没有真实模型或用户验收，也不证明更大语料上的泛化/统计显著性；没有替换已通过端到端验收的检索默认。

## 复现与下一步

已有 Rust 1.90、Python 3.10+ 环境即可，不自动安装依赖。输出必须是 `/tmp` 下全新目录：

```sh
python3 -m unittest discover -s scripts/query_diagnostics -p 'test_*.py' -v
PYTHONHASHSEED=1 python3 scripts/query_diagnostics/evaluate.py --out /tmp/recall-query-first
PYTHONHASHSEED=2 python3 scripts/query_diagnostics/evaluate.py --out /tmp/recall-query-second
cmp /tmp/recall-query-first/results.json /tmp/recall-query-second/results.json
```

独立 `query-diagnostics.yml` 验证可复现性，产物只含合成 summary/results，不上传编译目录或本机路径。工作流绿色表示方法运行成功，不表示候选策略优于默认。

下一步优先检查已经具备授权和原文复核的语义通道，找出无字面重叠候选进入共享召回的实际缺口；或者使用明确来源/用户维护的别名。fixture 向量只能验证接线与权限，真实语义质量必须另有固定模型实测。没有证据时，不用放宽单字门槛代替这一步。
