# 有界文本附件词法读取

普通 `search` 的 `all`/`events` 以及显式 `attachments` 目标，在 `brief`/`context`
模式下可以找到已保留文本附件的正文。共同入口 `recall_search(query)` 也合并同一
词法候选；`recall_fetch(id)` 按命中字节起点读回并分页。无需配置编码器。

## 已实现范围

- 仅支持声明为 `text/plain`、`text/markdown`、`text/csv`、
  `text/tab-separated-values` 或 `application/json` 的完整 UTF-8 原件。
- 完整 SHA256、声明大小、实际大小、UTF-8 和控制字符检查通过后才生成投影。
  原件中的 BOM、换行、标点和字节坐标保持不变。已识别 PDF、图片、压缩包不会按文本解释。
- 单文件最多 1 MiB；候选扫描阶段最多检查 256 个附件、读取 16 MiB 原件。
  失败读取同样消耗扫描预算；缺失、损坏、不支持及超限在 `coverage.attachments` 明确报告。
  16 MiB 不是端到端 I/O 总上限：共同入口还对最多 10 个候选逐个重新校验原件，
  正常额外读取至多 10 MiB。同对象多声明的选择，每次候选复核另有 256 声明/
  16 MiB 独立预算。后续每次 fetch/read 分页也重新验原件，而非只读取返回片段。
- 附件引用形如 `attachment:evt_…/sha256`，绑定所属 Event 与内容寻址原件。
  返回 `kind=attachment`、`projection=attachment.utf8/1`；不会改写 Event.text
  或把文件内容伪装成上传者说过的话。`sources` 返回所属 Event 引用。
- 每次搜索和每页读取重新检查范围、当前修订、抑制和原件摘要；连接撤权仍由既有
  受管理读取服务在每次请求时校验。游标、定位符、对象摘要均不是授权凭据。
- `read` 支持单个附件引用及 `next_cursor`；不接受任意路径或附件会话图导航。
  批读附件需拆成单引用请求。纯 Event 会话发现/邻接读取维持原合同。

## 诚实边界

这是每次从正本重建的有界本地词法扫描，尚未持久化到 SQLite 附件倒排索引，
这条词法路线本身不使用附件语义向量；另有默认关闭、须单独批准的本机附件语义索引。文件名别名仍保留在所属 Event；附件正文使用独立投影。
未覆盖的文件不等于没有相关内容。导入时保存的 `content_indexed=false` 是原件导入
状态，不是当前检索覆盖证明；应以本次 `coverage.attachments` 为准。

未做 PDF/DOCX 提取、OCR、编码猜测、脚本执行、群聊或 Pages，词法路线也不会向模型发送附件。
候选相关性保持 `unassessed`。禁用 Event 编码索引不等于撤销本地附件读取权限；
需要撤销连接或收窄其范围。真实模型采用附件的质量与真实用户验收仍需独立验证。

## 验证

新增 `attachment_recall` 使用合成原件测试正文关键词、消息/附件区分、精确 UTF-8
分页、对象损坏/缺失/二进制/大小边界、符号链接、跨范围、来源修订/抑制和连接撤权。
既有合成生产链从官方结构等价 ZIP 实际导入附件，验证普通 search → shared
recall_search → recall_fetch → 撤回，不把固定数值编码器当作真实模型质量验证。

桌面结果明确标为附件正文，点击定位所属消息。「带到任意 AI」可单独选择受支持附件正文，
复制时保留独立 attachment 类型、父消息引用和原件 SHA-256，不当作上传者原话。
每次预览/复制重新验证当前来源和原件；完整分页仍使用只读读取入口。复制包预算、
附件关联验证的额外 I/O 和系统剪贴板边界见 [交接说明](portable-context.md)。
