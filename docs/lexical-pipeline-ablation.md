# 合成词法消融：接入真实生产分块与检索链

这是上一轮[单词法消融](lexical-ablation.md)的应用链补验。只增加合成例程、临时实验 worker 和 CI，生产默认分词、排名及配置没有修改。

## 这次真正经过哪些代码

1. 生产 `Vault.capture_batch` 写入普通 user/assistant Event；生产导入器另外读取一个结构等价的合成 ChatGPT 附件 ZIP。
2. 生产 `LocalEvents.refresh_step` 切分 UTF-8 原文、提供相邻上下文、发送有界批次并发布同一代次的 SQLite 索引。
3. 生产 Python worker 计算语义 top100、每 Event 聚合、词法/语义 RRF，返回真实来源证据。
4. 生产 Rust 再核验当前 Event、完整来源集合、范围和 hash，并在有界候选中把完整精确编号优先。
5. 生产共享 `recall_question` 执行最终响应预算，`recall_fetch` 实际读回第一条结果；末尾停用后检查旧检索与旧定位符都被拒绝。

每次创建全新合成资料库。例程把编译时嵌入的核心源码 hash 与当前工作区核对，防止拿旧例程测试新源码；结果也记录 Python 与评测代码 hash。没有复制用户资料、执行外部 Agent、下载模型或做真实模型推理。

实验只把生产 Python 包复制到临时目录，在那里替换词法候选的排序函数。count 使用原函数；BM25 与 b=0 使用生产生成的 chunk 边界和同一词项集合：逐块 tf、全部可见 chunk 的 df/N/平均长度、同样的 postings/候选窗口，先选每个 Event 的最佳块，再取最多 100 个 Event。RRF、宿主原文验证、编号优先和响应预算都继续调用生产实现。实验统计额外读取合成 fixture，不是可发布的生产 BM25 存储实现，也不是性能基准。

CJK trigram/词 shingle 尚不符合现有 Rust 词项证据协议，本批没有假装把它们接进来。它们仍属于上一轮的独立词法试验。

## 固定合成范围

- 277 条合成消息，加一个附件专用事件；过滤其他 scope、撤销和被修订替换的旧事件后，有 274 个可索引 Event。
- 57 个查询：46 个预设有答案来源的查询，11 个预设无答案查询。
- 三种词法排序：生产 distinct count、BM25 `k1=1.2,b=.75`、BM25 `b=0`；各运行 256 与 8192 字节两种真实 chunk 设置。
- 固定数值 HTTP 提供器给 206 条干扰消息较高 cosine，普通来源较低 cosine，查询使用固定向量。它专门检验两路冲突与精确来源补回，不代表任何真实 embedding 模型。

## 主要发现

### 长来源的行为确实受真实分块影响

256 字节时实际形成 364 个块，单个长 Event 最多 42 块；8192 字节时为 275 个块，最多 2 块。每个阶段都核对一个 Event 不会重复占结果槽。

上一轮把整个长消息当一个块，BM25 `.75` 把三条详细来源压到第三位。这一轮 256 字节真实分块下，三条详细来源都回到首位；8192 字节时仍先返回简短消息。某个详细来源在大块设置下先被 RRF 放到第五位，再由编号优先层提到第二位。这说明不能把整段离线排名直接外推成产品行为，也不能仅据小样本选择 b。

### 编号优先层不是纸面检查

专门构造只含一个编号的高语义/高词法干扰项。原始 RRF 结果的前五条不含目标完整双编号来源；生产 Rust 核验后，完整双编号来源在六组中都被提到第一位，并保留到最终共享响应。

另一个完整编号跨越 256 字节 chunk 边界，且来源不在 semantic top100。它仍通过独立词法进入候选，最终保留完整原文字节证据。语义排名为 null，没有把这条命中伪装为语义 top100 命中。

### 没有证据支持直接替换生产默认

下表是固定、对抗性数值通道下的最终共享结果，仅用于本合成链对照。分母都是 46 个正例。

| 分块 | 词法策略 | Top1 | Top5 |
|---|---|---:|---:|
| 256 | 生产计数 | 28/46 | 35/46 |
| 256 | BM25 `.75` | 28/46 | 34/46 |
| 256 | BM25 `b=0` | 28/46 | 34/46 |
| 8192 | 生产计数 | 28/46 | 35/46 |
| 8192 | BM25 `.75` | 25/46 | 34/46 |
| 8192 | BM25 `b=0` | 27/46 | 33/46 |

固定语义通道会对所有问题给出干扰候选，因此 11 个无答案查询均仍返回候选。这不等于生成错误答案，但明确说明“检索有返回”不能当作可回答性。全体查询都有候选或字节窗口截断，结果按原有协议如实标记；共享响应始终不超过 8KiB。源角色和未评估相关性继续保留，没有运行事实采用或答案生成评测。

## 附件边界也是真实导入结果

合成 ZIP 中含 `pipeline-attachment-note.txt`，文件原件独有的标记没有出现在消息正文中。导入后：

- 旧关键词入口可按附件名称找到所属事件。
- 该事件正文仍为空；查询附件原件独有标记不会得到正文词法命中。
- 它不会混进普通对话本机向量索引。

所以长对话正文、可搜索附件名称、已提取的附件全文是不同能力。本批没有附件全文提取器，也没有把长对话样本称为附件全文检索验证。

## 复现与验收

```sh
python3 -m unittest discover -s scripts/lexical_ablation -p 'test_*.py' -v
cargo fmt --all -- --check
cargo clippy --locked --example synthetic_lexical_pipeline -- -D warnings
cargo build --locked --example synthetic_lexical_pipeline
python3 scripts/lexical_ablation/evaluate_pipeline.py \
  --repo "$PWD" \
  --binary "$PWD/target/debug/examples/synthetic_lexical_pipeline" \
  --out /tmp/recallcard-lexical-pipeline-new
```

必须用不存在的新输出目录。支持 `--modes count_production` 与 `--chunk-sizes 256` 进行局部诊断，局部运行不能称为完整矩阵。

本地六组实际链均通过，16 项方法测试、Rust fmt 和例程 strict clippy 通过。`lexical-ablation.yml` 增加独立生产链作业，完整跑六组后仅保存合成 fixture 和汇总证据；远端结果以对应提交的 CI 为准。

仍未验证：真实用户语料、真实模型召回、答案正确性、大库性能、其他桌面平台、中文词分词器、新 ngram 证据协议及生产 BM25 索引迁移。合成问题及标注由实现者编写，同构例不独立，不作显著性或泛化质量声明。
