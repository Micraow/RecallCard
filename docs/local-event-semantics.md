# 普通对话与单独批准附件的本机语义索引（候选功能）

这个入口让普通用户原话和助手回答直接参与本机向量检索，不要求先整理成 Memory。默认关闭；需要 Python **3.11+**（SQLite 分配硬上限）及用户已经安装、确认的 OpenAI-compatible embedding 服务。旧功能的 Python 要求不因此改变。RecallCard 不下载、启动或代管模型。

## 在应用中使用

1. 在设置中选择“配置普通对话本机索引”。填写数字回环地址、模型名称、模型文件版本、Tokenizer/池化版本和向量维度。
2. 分别选择当前范围的普通对话正文、附件正文以及新问题按需编码。三项默认都不选，互不继承，也不继承 Memory 或云编码的批准；旧配置缺少附件字段时始终视为未批准。下一屏核对地址、范围和数据，再确认保存。
3. 保存配置不会开始编码。点击“更新普通对话索引”（启用附件时为“更新已批准资料索引”）才分批处理；可在当前批完成后暂停，返回设置后继续。离开设置不再启动下一批。
4. 索引完成后，在首页输入问题并“准备这次对话”。显示当前 Event 候选、角色和时间；选择来源、预览实际复制内容，再复制到任意 AI。向量候选不等于事实或答案，助手的话仍标为助手来源。
5. 新增、修改、撤回、恢复原话，或替换、损坏、丢失已批准附件原件之后，需要更新索引。旧快照拒绝当作当前完整覆盖。停用本机索引保留原话和可重建的派生缓存。

只有数字回环 HTTP 地址受支持；拒绝域名、凭据、代理和重定向。回环地址不证明该服务内部完全离线，请确认服务的数据去向。此入口没有云回退。未配置这个新入口时，原有词法/Memory 路径保持原样；本机服务或快照不可用时明确报错，普通关键词搜索仍可用。

## 保存内容与校验

- 原 Event 和保留附件原件是正本。SQLite 只保存独立来源引用、角色、时间、范围、hash、词法派生项和 float32 向量，不保存正文。正文仅存在于有界编码批次与最终核验片段。
- 仅当前批准 scope 中、未撤回、未被合法修订替换的普通 user/assistant Event 可编码。排除上下文注入、整理任务输出和推理草稿。普通对话批准不含附件；只有附件项单独批准后，才读取同一当前父事件下的安全 UTF-8 原件。附件是独立证据，role 为 null，不把它的内容归为上传者原话。
- 每个向量绑定完整原文 hash、UTF-8 起止范围、片段 hash。查询返回后再核对当前 Event／附件原件和整个来源集合；磁盘 manifest 不能自行成为权限证明。
- 完整模型空间包含模型及文件版本、Tokenizer/池化版本、维度、文档/问题指令、规范化、切块版本和地址。变化时使用新空间，不能混用旧向量。
- 新快照完整提交后才发布；中断可续建；相同输入复用已编码向量。成功更新时同步移除撤回或替换来源的派生索引。原话不因缓存回收被删除。
- 新问题按需编码，最多缓存 32 条问题向量，不保存问题正文。缓存空间不足时允许本次查询使用已获得的向量，标记 `local_uncached`；不会改用远端编码。

## 资源边界和当前取舍

- 每次编码最多 8 块，同时受总输入 64 KiB、向量值数量和单请求上限约束。片段为不重叠 UTF-8 范围，可配置 256–8192 字节；空白块跳过但原文偏移不改变。
- 来源清单最多 100,000 个文件/来源，1,000,000 个块；目录深度、路径总长度、单个 Event 和 JSON/协议帧都有硬上限。逐 Event 校验，不一次读取全部聊天正文。
- SQLite 和 journal/WAL/SHM 的磁盘总预算可配置 16–512 MiB。数据库可用空间保守限为预算约三分之一，为更新和回收的事务日志预留空间；不是承诺能容纳固定数量的会话。
- 查询逐页读取向量，每条原话先选最佳块，再选前 100 条候选；长 Event 不会独占候选槽。界面最多 20 条、每段 2048 字节及整体输出预算。SQLite 在取行前限制单值分配，损坏的大 BLOB 不会先全部加载进 Python。
- worker 队列、超时和空闲寿命有界。模型进程的内存不在 RecallCard 数据库预算内。当前只实现 float32，没有声称支持量化或 ANN。
- 当前每次批次和查询还需检查文件清单。Unix 下使用进程内身份校验缓存；非 Unix 目前重新流式核验来源。大库首次建索引、Windows 冷启动和真实模型推理性能尚需单独测量，不能把纯向量原型的计时当作此应用链的结果。

## 验证边界

Rust 集成测试使用真实 Rust → Python → 回环 HTTP → SQLite → 原 Event 路径，编码器返回固定合成向量。覆盖独立批准、无 Memory 直接检索、撤回/增补、版本隔离、损坏缓存和跨 scope 伪造拒绝。native GUI 旅程也明确使用合成编码器，并核对保存配置不发送正文、点击更新才编码、结果可进入复制预览。

这些测试验证真实传输和应用合同，不验证真实模型的同义理解、召回率或用户电脑性能。选定并获准使用实际本机模型后，应另测同义改写、无关问题、否定、时间变化和用户/助手角色，记录漏召回与错误候选，不能复用合成向量成绩。

## 附件独立投影与批准

- 附件来源使用 `attachment:evt_<父事件摘要>/<原件 SHA-256>`，投影为 `attachment.utf8/1`。词法扫描、语义候选、分页与手动复制共用安全文本验证及快照计算，不拼入 Event 正文。
- 仅支持已经保留、类型声明一致的 UTF-8 文本、Markdown、CSV、TSV、JSON；摘要、字节数、原件类型和控制字符均需通过核验。不执行文件，不做 PDF 提取或 OCR。
- 单文件上限 1 MiB；每次语义来源规划最多检查 256 个声明，读取预算 16 MiB，失败与重复声明也占预算。来源规划只检查当前授权父事件声明，不枚举整个 objects 目录。候选复核及后续分页会额外读取所选原件，不承诺端到端仅 16 MiB。
- 语义 epoch 额外绑定所选附件的文件身份、大小、修改时间，以及 Unix ctime；非 Unix 为防同长度改写并还原 mtime，另读取有界原件计算当前摘要，因此每次快照校验也可能产生最多 16 MiB 额外 I/O。最终候选仍验证完整 SHA-256。缺失、损坏、超限或不支持的附件会跳过并标明 partial，普通 Event 可继续建索引。已发布快照遇到对象变化时保守要求刷新，不能继续冒称完整覆盖。
- 撤销附件编码批准使旧附件语义配置绑定和候选失效。只批准附件可建立独立附件索引，包括正文为空的父事件；只批准新问题不能建立任何正文索引。兼容旧 Event-only 查询配置，不因此允许新正文编码。
- 问题向量仍由独立 query_approved 控制；正文按来源种类分别核对批准，排队任务在实际 POST 前重查配置。配置保存本身不编码，不启动任何模型。
- 共同读取入口合并同一附件的词法和语义命中，不重复占据候选槽。查询向量复用、模型空间隔离、撤回与跨 scope 校验仍适用。覆盖为语义仅表示通道已运行，不表示相关性或可回答性已校准。

新增附件测试使用固定合成向量，目标是证明零词法重叠候选能够进入既有授权与读取链。它不是同义召回质量测试。已有普通 Event 真实模型合成验收独立记录在 [真实编码器说明](real-encoder-synthetic-ci.md)；其模型和阈值不能自动视为附件质量结论。
