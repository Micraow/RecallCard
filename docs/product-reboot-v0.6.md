# RecallCard 全链路重做规格 v0.6

日期：2026-10-08。状态：重做设计与实施合同，**不是已实现功能清单**。

本稿依据最初讨论的用户消息、两份设计基线、当前真实界面反馈和官方导入失败复现。完整原始对话与真实归档只在私有验证目录保留，不进入源码仓库。旧版本能走完窗口测试，不等于已经完成产品目标。

## 1. 要交付的产品

让用户在 Web Chat 与本地 Agent 之间切换时，不必重新介绍自己、搬运背景或经营一套记忆流水线。

RecallCard 是一个本地上下文运行服务。CLI、桌面、浏览器扩展和 MCP 是同一服务的入口。桌面负责看懂、纠正和控制状态，日常捕获、增量整理和按需召回由服务完成。

### 必须延续的原始约束

- Rust 主体、按需 Python worker，本地单体；不要求用户先部署一组数据库服务器。
- Event 与 Memory 是可读文件正本，Git 提供版本与显式同步；索引、聚合视图可重建。
- Web 与 Agent 都能作为输入和输出；统一记录 message、tool call/result、file、citation 和 trace 的结构。
- 内容先可靠捕获并可检索，再整理。尚未整理不是无法接续的理由。
- 小而稳定的通用 profile/bootstrap，模型主动按需调用 search/read/sources；不根据用户刚打的几个字猜 Topic。
- Web 最终 Send 由人点击。自动捕获、执行已授权的只读查询、准备草稿与解析动作不需要退化成人工搬 JSON。
- 云端整理模型与 embedding 可选，费用可控制；没有 API 时的人工 Web 整理只作为高级备用方式。
- 不建立复杂认知类型树，不默认引入独立 Episode 正本；不为展示图谱增加必须维护的基础设施。
- 产品仍是跨平台的个人上下文层，不变成新的聊天客户端，不与其他项目耦合。

### 明确淘汰的默认体验

1. 让用户逐段勾选才能进入日常整理。
2. 把生成提示词、复制、粘贴 JSON、逐次批准作为正常整理入口。
3. CLI 和 GUI 分别维护一套业务流程及状态。
4. 堆叠高级表单、重复导入入口、空卡片、内部 ID 和术语。
5. 以测试数量替代“换客户端仍能直接接续”的实用性验证。

## 3. 全部入口共用的架构

### 3.1 分层边界

1. **领域与文件正本**：事件身份、来源、时间、记忆修订、抑制/遗忘、受保护更改、事务。不得依赖 GUI。
2. **应用服务**：导入、捕获、查询、整理、连接、迁移、备份。返回类型化结果，不返回一段需要前端猜测的错误字符串。
3. **本地运行服务**：持久任务队列、调度、单实例租约、取消/恢复、预算、模型 worker 生命周期。关闭 GUI 不取消已允许后台运行的任务。
4. **接入层**：CLI、Tauri、MCP stdio、Native Messaging 均调用同一应用服务与任务模型。
5. **表现层**：桌面与扩展只保存视图状态，不决定数据权限、不复制导入或整理算法。

保持一套本地发行物。GUI 正常启动时可按已授权配置启动/连接服务；CLI 能独立使用。Unix socket / Named Pipe 优先，不为方便随意开放 localhost 网络服务。

### 3.2 共同任务合同

任务状态统一为 queued、running、paused、needs_input、failed、completed、cancelled。任务记录包含类型、阶段、来源游标、已提交数、重复数、跳过原因、可重试原因和时间；命名与序列化在一个合同中定义。

- CLI 可等待或返回 job_id；GUI 订阅同一任务事件。
- 进度显示已知的实际计数；未知总量不显示伪造百分比。
- 取消不撤销此前已明确提交的数据，结果说明提交边界。
- 崩溃恢复不能把完成任务重新执行；租约、检查点和来源版本共同判断。
- 多次点击复用同一任务请求 ID；幂等范围必须定义到来源/会话/事件修订。
- 原文不能因日志/错误输出被泄露；具体格式/限制诊断与原文内容分开。

## 4. 重新设计 CLI

以下是目标接口，实施前先形成可执行合同；不是当前命令说明。

| 任务 | 目标命令形态 |
|---|---|
| 首次配置、验证环境 | `recallcard setup`、`recallcard doctor` |
| 启动和状态 | `recallcard start`、`recallcard status` |
| 直接导入官方包或目录 | `recallcard import <path>` |
| 查询原话与记忆 | `recallcard search <query>`、`recallcard read <ref>` |
| 连接客户端 | `recallcard connect <client>`、`recallcard connections` |
| 查看与控制后台工作 | `recallcard jobs`、`recallcard jobs pause/resume/retry <id>` |
| 记忆纠正、查看出处 | `recallcard memory show/edit/sources <id>` |
| 备份和迁移 | `recallcard backup`、`recallcard migrate --dry-run` |

人在终端得到简短可读的结果、进度与下一步；`--json` 输出版本化结构，stdout 不混日志。MCP/stdin 机器协议永远不混用户文案。退出码区分格式不支持、资源限制、授权不足、模型不可用、冲突与内部错误。

配置一次来源范围、模型目的地与预算后，任务使用明确的持久配置。不能要求每个常规批次重复输入多个 approve 参数。无效或撤销的配置必须停在 needs_input，不能猜测同意。

旧命令提供兼容或可操作的弃用提示，不静默改变原命令的数据含义。迁移必须能在副本上验证和回退。

## 5. 重做导入与捕获

### 5.1 官方导出是基本输入

已复现：合法官方导出可包含超过 16 MiB 的 conversations.json；旧 CLI 在预览前拒绝，GUI 丢失具体错误。不能把“请自行分批导出”当修复。

- 自动识别容器与平台，优先由结构与标识判断，不仅依据扩展名。
- ZIP 流式访问必要成员；大 JSON 使用增量会话解析与有界暂存，避免同时保留全文、完整 Value 树和全部归一化事件。
- 限制针对压缩炸弹、成员路径、总展开字节、单条异常消息、嵌套深度与任务资源；应公开阈值及恢复方式，不用偏小的单文件门槛拒绝正常存档。
- 保留会话分支、角色、原始时间与未知字段引用；不把导入时间冒充消息时间。
- 同一文件重复导入幂等；修订输入明确建立修订而不是误删旧内容。
- 先预检结构并给覆盖报告；处理期间可查看进度和部分已提交来源，完成后显示成果。不能伪称附件、隐藏内容或不支持片段已保存。
- 错误必须包含稳定 code、受影响文件/成员、原因、已写入状态、可采取的动作；详情可展开但核心原因不能抹掉。

### 已证实的旧实现边界与新回归合同

- 大小拒绝发生在 ZIP 目录审计阶段，而非文件损坏；新测试必须直接输入超过 30 MiB 的合成 conversations.json，并验证每个会话标题、分支和角色，不能只断言“解析没报错”。
- 旧 CLI 对每个事件重新扫描全部正本，累计读取随输入量平方增长。新提交器应一次建立来源版本索引，以有界事务块提交；块收据负责崩溃重放时正确区分新增与原有重复。
- DeepSeek 文件引用实际位于 fragments[].files；只检查 message.files 会把已跳过附件错误报告为零。URL/标题、文件身份/名称/大小均须结构化保留，未包含的负载明确标记 not_in_export。
- 部分工具片段仅有类型标识。保留其位置与缺口，但不能编造搜索结果、工具正文或可下载附件。隐藏推理与未支持片段分别计数。
- Event/Memory schema v1 不在本阶段破坏性改写。新增来源结构放入兼容 metadata；同一来源因新适配器补全结构形成正常修订，保留旧版本与原始时间。

### 5.2 日常来源自动接入

连接向导一次选择支持的平台、捕获范围和隐私排除。已授权的可见会话在稳定完成后自动捕获；不把流式半句、页面重渲染或注入的背景当新的用户事实。切换账号/会话使旧绑定失效。

原始事件即时建立文本检索，后台整理与 embedding 的失败不阻塞基本搜索和已捕获原文接续。所有未知平台明确未支持，不展示假连接。

## 6. 后台记忆整理是产品能力

### 默认流程

完成首次模型/本地模型配置与范围授权后：新事件进入队列 → 安静期/累积阈值触发 → 有界投影 → 模型提取候选 → 检索旧记忆进行整合 → 确定性校验/提交 → 更新视图与索引。

用户不需要挑选每段来源。正常可回退更新按配置自动应用并记录变化；有矛盾、涉及受保护事实或扩大使用范围时才进入待处理列表。每条结果能回到证据，不能把 assistant 建议当用户已确认。

### 运行约束

- 源版本、投影版本、模型配置、预算和授权共同固定一次工作；重试不重做已成功部分。
- 原始记录保留，候选失败不会破坏现有记忆。
- 遗忘/撤权即时从读取与排队投影中剔除；摘要不能使删除内容复活。
- 同名实体、计划与完成、旧事实与当前事实分别处理；未知时间保持未知。
- 不把高置信度数字当真实保证；不能由模型扩大自身数据或网络权限。
- 模型未配置时明确“已保存，可搜索；后台整理尚未启用”，提供一次配置入口，不强迫转去手动粘贴。
- 云模型初次启用说明具体接收方、范围与花费上限；密钥由支持的本机安全存储或受保护启动渠道持有，不进入 Git。
- 月度/单次预算、最大并行数、暂停、失败退避、缓存与实际用量可查。价格估计是估计，不将宣传报价写成保证。

### 缓存与检索

固定系统说明、工具定义、稳定 bootstrap 排在可复用前缀；当前查询与临时材料置后。会话使用明确快照与必要增量，不为每次读取重写 profile。失效事实和撤权仍立即生效，不为了缓存保留旧权限。

保留 bootstrap/search/read/sources 四个读取能力。文本召回覆盖尚未整理的原文；向量索引可增量更新，失效或离线时清楚降级。不能靠默认 top-k 代替时间、实体、来源与权限判断。

## 7. 接入与团队上下文

连接页展示实际状态：未配置、已配置未验证、可连接、最近成功读取、失败。安装文件存在不等于宿主已调用，更不等于模型已经理解。

Agent 的启动/恢复/压缩后接入稳定 bootstrap；后续由模型调用四个读取能力。Web 扩展在明确站点与范围授权后准备上下文，解析合法请求并执行只读检索，把结果写入可见草稿；最后发送仍由人完成。页面身份不明则停止注入，保留用户草稿。

个人偏好、项目事实、用户设定的规则、可复用技能在呈现和权限上区分。规则不由观察推断成授权；生成技能需要审核才能启用执行。项目可以继承已批准的规则/资料/技能，个人聊天不随项目共享。

团队机制先借鉴可版本化上下文包、明确归属和授权边界；是否实现多人托管是独立范围，不能让个人版默认依赖服务端。同步与分享必须分开：配置 Git remote 不代表将所有个人历史公开。

## 8. GUI 重做

不以旧表单为约束。采用稳定的应用壳、内容列表/阅读区、按需侧栏；宽屏不把按钮拉成长色块，窄屏不把两张空大卡叠起来。

### 主要目的地

- **记忆**：可读的个人与项目上下文、变化、来源和纠正入口；展示实际内容而不是流水线参数。
- **来源**：平台/会话/文件与完整状态，一处添加入口；失败就地解释，可恢复，不藏到全屏底部。
- **连接**：哪些 AI 能读取什么，配置与真实连通性；安装/授权向导只在需要时出现。
- **活动与设置**：后台进度、需要决定的冲突、用量和控制。日常无事时低调，不用空计数卡占首屏。

首次体验只完成必要连接与模型/预算选择，可先离线导入。日常打开直接看已有内容；用户不需要理解 Vault、DreamJob、JSON schema 才能用。

实现上以组件、类型化状态和任务订阅替代整页字符串重绘。CLI 与 GUI 的导入、错误、范围和任务状态只定义一次。版本显示来自构建元数据。

## 9. 迁移与实施次序

完整重做不等于销毁用户数据。先保存旧发行物与 schema，再在副本上迁移 Event/Memory/抑制记录/历史；检查计数、身份、引用和可见性。未提交草稿和连接状态不能伪装已迁移。完成验证前不删除旧库，不覆盖旧备份。

1. **合同与真实输入**：完成官方完整归档导入、分支/角色/时间/重复/失败诊断，以及同一任务从 CLI/服务/GUI 的一致性。
2. **运行服务纵切**：持久配置、后台任务、模型 adapter、增量整理、错误恢复和费用控制。离线 fake-provider 仅验证协议，不宣称记忆质量。
3. **新 GUI 与接入**：基于同一服务实现全新内容界面和一次连接流程；实际 Web/Agent 接续作为验收目标，不以静态截图完成。
4. **迁移与发行**：真实归档与用户任务全链路，安全备份、副本迁移、并排安装和来源可追溯的包。

阶段代码可持久保存，但不能每个内部小修就作为新版产品交付。原生构建优先复用已验证且源码完全一致的程序；应用改变必须重建，不能用旧二进制验证新代码。

## 10. 验收以结果为准

1. 未预处理的官方完整归档能导入并正确给出新增/重复/跳过/失败；中断可恢复，无内存失控。
2. 不启动整理也能查询刚捕获的决定、原话、分支和来源。
3. 已配置整理后无需挑选/复制/贴 JSON，新证据能更新记忆并保持历史；错误与冲突可解释。
4. 修正事实、撤权、遗忘和停用后，下一次召回遵循最新状态，旧任务不能复活内容。
5. 换一个已连接客户端自然获得稳定 profile，并可按需找到另一客户端刚形成的上下文。
6. Web 上的用户草稿不丢，所有自动路径均零发送事件；实际支持网站分别验收。
7. CLI 和 GUI 返回同一任务、同一计数、同一错误类别，不产生两个导入实现。
8. 无模型、离线、额度耗尽、权限撤销、崩溃和多实例均有可理解的状态和恢复路径。
9. 项目上下文继承有效，个人来源不越界；规则与技能的使用不创造新授权。
10. 包在独立安装目录和升级副本中可用，文档与实际版本一致。真实资料只做本地验证，公开回归使用结构等价的合成样本。

模型理解效果、真实网站适配和实际宿主接入必须分别报告，不把 fixture、协议通过或页面点击完成写成已实现“统一记忆”。
