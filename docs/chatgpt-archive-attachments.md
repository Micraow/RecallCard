# ChatGPT 官方归档：消息与附件

## 使用与验收

桌面「来源」页选择官方 ZIP，或使用统一导入任务入口：

```bash
recallcard --vault ./local-vault init
recallcard --json --vault ./local-vault import ./official-export.zip --scope personal
```

1. 导入完成后查看报告中的消息数、附件引用数、已保存原件数和缺失原件数。这些附件计数按消息引用统计；同一文件被两条消息使用时计两次。
2. 在来源记录里展开原消息，核对附件原名、导出别名、状态、声明类型及实际识别类型。只有附件而没有文字的消息也会保留。
3. 在已授权范围内，用附件名或别名检索对应消息，再查看其上下文。附件名参与本地词法匹配；附件正文尚未提取或建立向量。
4. 重复导入相同 ZIP 不应增加同一来源的重复 Events，也不会重复保存同一哈希原件。原件后来补齐时，消息追加可审计修订。

旧 `import --file ...` 是兼容入口，仅选择 ChatGPT 当前分支。需要完整分支及 ZIP 附件时使用上述位置参数入口或桌面来源页。

## 保留什么

- 以 `mapping` 的 `parent` 为关系依据，保留所有导出的可见分支、原始节点/消息 ID、当前路径和时间。没有 `children` 时反向建立子节点列表；不按时间猜测父子关系。
- 跳过隐藏推理内容，保留可见节点原父编号、最近可见父节点和中间省略节点数，避免把隐藏内容伪装成普通回答。
- `metadata.attachments[].id` 与已知 `sediment://file_...` 图片引用关联到同一消息。`library_files.json` 补充文件元数据，`conversation_asset_file_names.json` 只提供别名，`export_manifest.json` 提供逻辑文件与物理成员的显式映射。
- 清单限定在 `conversations.json` 所在导出根目录，不跨独立导出根目录拼接来源，不按相同文件名猜测文件身份。
- 保留附件声明 MIME 的冲突；原件存在时仅用 magic 前缀识别 PDF、PNG、JPEG、GIF、WebP、ZIP，否则标记不透明字节。
- `is_do_not_remember` 来源不会被后台自动整理成记忆。来源记录仍可审计。

## 缺失原件与安全边界

用户提供的精简 ZIP 可以没有 `.dat`。此时消息和附件元数据仍可导入，状态为「原件缺失」，不会把缺失当作已读取或已索引。只读预览即使看到了字节也只标记「未保存」，不能冒充已入库。

原件按 SHA-256 保存到本地 Vault 的 `objects/`，不是以附件显示名生成路径。写入采用私有暂存文件、流式大小和 CRC 校验；整批解析、脱敏和 Event 校验完成后才开始规范提交。已有同哈希对象会校验后复用，损坏对象不会被静默覆盖。暂停或解析失败不会把尚未校验的附件作为事实发布。

不会执行附件，不解压附件内部 ZIP，不打开浏览器内容，不做 OCR，也不把附件发给模型。magic 识别不是恶意文件扫描。发生磁盘或进程级故障时，已有分块提交按原恢复协议处理；可能留下未引用的不透明对象，不承诺跨全部磁盘写入的单次事务。

默认输入总字节上限 1 GiB、累计展开上限 2 GiB、ZIP 成员上限 2048；单会话/附件目录 JSON 上限 16 MiB。整个 `conversations.json` 使用逐会话读取，不受单会话上限误伤。单个附件流式处理，不使用 16 MiB 会话内存上限。资源超限明确失败，不截断为成功。

当前不支持分片附件和 ZIP64；文件引用中的页码、行号等细粒度 citation 尚未映射。群聊与 Pages 不属于当前支持范围，导入报告会标记跳过。

## 验证范围

`tests/application_chatgpt_assets.rs` 全部使用合成输入，覆盖精简包、附件-only、真实父链规则、别名与 MIME 冲突、哈希去重、文件名词法召回、范围/撤回过滤、恶意路径及 Unicode 路径别名、目录错配、CRC/大小不符、后部超限零提交和不透明脚本字节。前端 contract 测试覆盖状态投影、真实 React 渲染与文件名转义。

这些测试不代表已安装浏览器扩展的登录态验收，也不代表 ChatGPT 网页会自动读取 MCP 上下文。原始附件的正文提取和实际文件格式兼容性需单独验证。
