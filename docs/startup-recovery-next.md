# 启动后回到上次的资料

本改进位于独立工作分支，基于0.5候选版，不属于已交付安装包。当前阶段只做本地后端、界面状态及跨目标编译检查，不新增Actions运行。

## 用户会看到什么

- 第一次打开时仍是「开始使用」；不要求先选目录或填写配置
- 用户明确打开资料后，程序记住这个位置和当前资料范围。再次启动直接回到这里
- 如果最近一次导入尚可继续，直接显示已经处理的数量及「继续导入」。只查状态，不自动恢复写入
- 最新任务已经完成时，不把更早的暂停任务强行拉回首页；这些任务仍可从原有导入历史入口检查
- 资料已打开但设置无法保存时，仍可正常阅读，只提示下次可能需要手动打开

## 不把故障伪装成第一次使用

原位置丢失、目录被替换、权限改变或配置损坏时，显示重新选择入口，不在原路径自动建立空资料库。保存的位置通过原生宿主固定配置文件记录；导入文件和网页不能提供任意恢复路径。

配置只保存必要位置、文件身份、权限快照及资料范围，不含对话、记忆、凭据或待确认写入令牌。配置放在资料库外，不参与Git同步。恢复时重新核对目录和格式标记，并使用不会补建目录的只读打开路径。

## 验证范围

本地回归覆盖首次无设置、真实临时资料库重启恢复、缺失/替换/链接/权限变化、保存失败后的可读性、资料范围、启动只读、暂停任务恢复入口、单次明确继续以及迟到设置保存顺序。界面测试加载真实应用模块，IPC返回由合成边界提供。

这不代表下一阶段原生窗口验收已经完成，也不替代当前0.5候选版的33步标准Linux验收。
