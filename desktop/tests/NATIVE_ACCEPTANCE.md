# 真实桌面产品闭环验收

`native_smoke.py` 使用编译后的 Tauri 程序、真实 WebKitGTK、系统文件选择器和桌面剪贴板。所有资料都在临时目录中合成；不读取真实聊天，不调用模型，也不替换前端 `invoke`。

## 运行

Linux 需要标准系统包提供的 WebKitWebDriver、Xvfb、AT-SPI、xdotool、xclip、scrot、openbox，无需额外的驱动代理。Python 使用安装了 `python3-pyatspi` 的 `/usr/bin/python3`。

```sh
dbus-run-session -- xvfb-run -a -s "-screen 0 1440x1100x24" \
  /usr/bin/python3 desktop/tests/native_smoke.py \
  --application desktop/src-tauri/target/release/recallcard-desktop \
  --cli desktop/src-tauri/target/release/recallcard \
  --artifacts /tmp/recallcard-native-acceptance
```

桌面按钮、输入框、选择框和确认窗口由 WebDriver 操作；文件路径通过原生选择器输入。DOM 脚本仅观察状态、读取可见控件值或滚动，不执行产品命令。CLI 用于读取 canonical 结果和原有 Native Messaging 安装测试；新增的导入、整理、记忆编辑、随身背景选择及范围切换全部经过窗口。MCP 检查启动 GUI 实际生成的组件，完成初始化后调用只读工具，不使用外部 AI 宿主。

测试在启动驱动前将 `XDG_DATA_HOME`、`XDG_CONFIG_HOME` 和 `RECALLCARD_STATE_DIR` 指向同一个测试临时目录下的 `data`、`config`、`state`，驱动及应用继承此环境。默认起步验收在任何点击前再次核对隔离路径，已有默认库、隔离配置缺失或符号链接越界均停止；不会访问用户真实默认目录，也不改变安全设置。只有点击“开始使用”后的实际文件和可见导入页均成立才算通过。

高级单文件入口在预览页展示文件、数量、资料库与范围后，点击一次“确认导入 N 条记录”即保存。
取消验收在这个按钮之前执行，随后重新选文件并审查；确认后检查没有第二层弹窗。
JSON/ZIP 的 canonical Event 不写入、重复导入去重及来源/角色/时间断言继续保留。

默认的“选择导出文件”入口使用标题为“选择导出文件（可多选）”的真实 GTK 文件选择器。新增样本目录只放两份合成 DeepSeek JSON；通过路径栏进入目录，点击 AT-SPI 核实的可见文件行，再以真实键盘 Ctrl+A 多选。提交前必须读取两份文件的实际选中状态，不能用应用命令、JavaScript 赋值或把多文件路径塞进单文件入口代替。多出其他文件、文件行不可见、焦点丢失或原生确认失败时立即停止，不盲目重试。

检查数量后只点击一次“导入全部 6 条消息”。`准备就绪` 只表示前台请求返回，不能证明后台写入完成；新增流程等待 DOM 中的“导入完成”和实际 6 / 6 进度，再核对新增/重复数量和 canonical Event。暂停、失败、读取进度错误、额外确认窗口或不一致数量均使验收失败。小样本不植入延时，也不强制抢点暂停；这四个新增原生步骤不声称已验收暂停/继续操作，恢复语义由独立的核心导入任务测试覆盖。

Linux 直接连接系统官方 WebKitWebDriver。能力字段 `webkitgtk:browserOptions` 与 `TAURI_AUTOMATION` / `TAURI_WEBVIEW_AUTOMATION` 环境来自 [Tauri 官方 Linux 映射](https://github.com/tauri-apps/tauri/blob/tauri-driver-v2.1.0/crates/tauri-driver/src/server.rs) 和 [原生驱动启动方式](https://github.com/tauri-apps/tauri/blob/tauri-driver-v2.1.0/crates/tauri-driver/src/webdriver.rs)。没有更换 WebKit、修改应用二进制或降低浏览器安全设置；移除的是曾多次在点击回执处断连的中间 HTTP 代理。

启动时必须先取得原生 `/status` 的 ready 响应，再创建唯一会话。标准输出和错误输出保存在 `webkit-webdriver.log`；结束时关闭会话并回收驱动进程。创建会话、点击、键入和确认均不因断连自动重发。

## 脚本中的 33 个检查点

原有 28 项流程和断言保持原来的相对顺序。新增第 2 步默认起步与第 30–33 步 DeepSeek 多文件流程尚未完成真实原生运行；下面是验收要求，不是通过声明。原有“打开已有资料库→取消→尚未打开资料库”的检查仍先执行，再验默认起步，随后从切换窗口继续原有建库过程。

1. 真实桌面首页与 Tauri 环境
2. 在隔离的临时 XDG 数据目录点击“开始使用”，不打开原生选目录窗口、不要求第二次确认，直接进入可见导入页；读取实际默认资料库格式标记及空 Event/Memory 目录，再通过可见“切换资料库”进入原有建库流程
3. 原生资料库创建、打开与取消
4. 保存首条个人补充并立即查找
5. 对话预览及取消均不写入 Event
6. JSON 导入及重复去重
7. 中文搜索与完整原文
8. ZIP 包含两个单会话 JSON，仅勾选其中一个；核对角色、原始时间、隐藏推理与跳过文件统计
9. ZIP 重复导入不改变 canonical Event；从已保存会话查看两条原始消息
10. 从会话选择来源，生成完整整理任务，并核对真实剪贴板包含规则、输出格式和完整 DreamJob
11. 根据复制出的真实 job 编号、摘要和来源构造合成 DreamResult，经普通输入框粘贴、逐条审阅及取消
12. 明确确认后实际保存 Memory 与 Dream 凭证
13. 追溯原始出处，重复带回相同结果不能再次发布
14. 记忆管理读取完整正文、证据性质和原始来源
15. 修改正文、标签与保护设置；取消不落盘，确认产生新版本
16. 解保护要求额外勾选，未勾选不能打开最终确认窗口
17. 遗忘规则实际隐藏记忆及其原始来源，搜索不再返回；资料文件保持不变
18. 主动查看隐藏内容、撤销规则；真实搜索重新返回记忆和来源
19. 通过 GUI 创建工作范围资料，切换个人/工作范围，核对记忆列表、搜索和整理来源隔离
20. 原有 Native Messaging 交换格式保存会话、重复去重与跨 AI 接续；复制内容核对真实剪贴板
21. GUI 生成的持久 MCP 配置可检索刚保存的会话
22. 从随身背景读取既有记忆全文及原始出处；勾选、预览、取消最终确认与取消选择均不写入 Memory 或 Event，当前实际背景保持原样
23. 明确确认后加入背景并保护，保留正文、证据与来源；真实剪贴板逐字等于预览，默认 MCP `bootstrap` 与 CLI 输出一致，GUI 接续的稳定背景段逐字一致
24. 已选记忆的普通标签编辑框不展示内部成员标记，编辑后保留背景成员与保护；个人/工作背景列表与实际文字隔离，两份 GUI 生成的 MCP 配置各自绑定范围
25. 移除受保护背景必须额外勾选，取消后重新审阅不沿用批准；移除后 Memory、证据、普通标签、原有保护与 Event 保留，默认背景不再包含该记忆，实际搜索仍能打开当前版本和来源

26. 从真实原生窗口导入 53 个合成会话、106 条消息，直接进入本批成果；默认窗口列表与窗口裁切范围的交集中至少完整显示 8 行，主导航只有会话和记忆
27. 长正文的接续操作保持首屏可见；往返记忆工作区恢复选中会话及列表位置；预览与真实剪贴板一致
28. 检索一条合成原话，按canonical Event引用核对确切结果、完整原文、平台及角色并定位相邻消息；返回后查询和选中记录恢复。BM25允许同时返回其他相关记录，不要求结果总数等于一
29. 将真实窗口缩至 860 像素宽，真实执行返回列表、重新打开、进入接续及返回阅读，检查对应内容和按钮可见，且不产生整页横向溢出
30. 从默认添加入口，在原生文件选择器中同时选中两份 DeepSeek JSON，看到两文件、两会话、六消息、当前资料库与个人范围；预览和取消均不写入 Event
31. 重新多选并只批准一次，等待真实后台完成态；六条消息保留原始角色、时区换算后的时间和毫秒，未知时间仍未知；两个兄弟回答与独立根均保存，隐藏 THINK 和附件原件/链接不进入 canonical Event，省略统计元数据保留
32. 再次多选同两文件，新增为零、重复为六，canonical Event 完全不变；从“查看已保存会话”打开分支会话，核对四条完整原文、角色、未知时间和三个分支末端
33. 多分支接续起初必须要求选择；通过真实可见选择框和键盘选择回答乙的实际 Event 引用，生成并复制仅含用户问题与回答乙的交接内容。返回阅读后通过回答甲的“从此分支继续”切换，旧预览清空；重新生成、复制的内容仅含问题与回答甲。两次真实剪贴板均须逐字等于各自预览，不混入兄弟回答、独立根、其他会话、隐藏片段或附件

随身背景检查在原有 20 个步骤完成之后执行，使用刚保存的同一条合成 Memory。后续引用由 CLI 读取的实际当前版本生成，不沿用先前编辑步骤的版本号。输入继续使用真实聚焦、全选与剪贴板粘贴；正文断言读取具体正文节点的 `textContent`，不依赖 WebDriver 对整块布局文本插入的空白。

生成的 `summary.json` 只有在全部检查点成功后才写入 `success: true`。每个检查点保留桌面及 WebKit 截图，原生文件窗口另留截图。失败保存错误栈及页面源码；成功另存 canonical Event、编辑前后 Memory、遗忘/恢复规则、Dream 凭证与复制出的完整任务。`canonical-evidence.json` 的 `background_selection` 还保留选择前、加入后、普通标签编辑后、移除后的 Memory，以及真实复制文字、接续文字和各范围的默认 MCP 背景。

新增的 `deepseek_import` 证据包含两份文件名、首次与重复任务的 DOM 完成状态、可见数量、六条 canonical Event、键盘所选分支引用与两份实际核对过剪贴板的交接文字。多选提交前另留选中态桌面截图；失败且窗口仍在时保留辅助功能树。

`default_workspace` 保存测试临时目录内的相对默认路径、实际格式标记、空 Event/Memory 数量与进入导入页时的 DOM 状态；不以模拟状态代替资料库初始化证据。

## 结果边界

编译、Python 语法检查、传输层单元测试、服务层测试和使用模拟响应的浏览器测试都不能替代本脚本的真实运行。只有对应提交的标准 Linux CI 运行成功，才可声明这些原生产品步骤通过。其他桌面平台及用户自己的机器需要分别验证。

已交付 v0.3 的 [标准 Linux 运行 37603515640](https://github.com/Micraow/RecallCard/actions/runs/37603515640) 通过原有 20 步；这是已有版本的证据。0.4的[37623800674](https://github.com/Micraow/RecallCard/actions/runs/37623800674)已完成全部28步；41e70dd程序由6dd1ba8验收脚本驱动，完整构建来源为37620418524，二进制逐项校验后复用。新结论不继承此前版本的通过状态。dot 云端电脑的内核 socket 限制仍在，本阶段不重跑或绕过该限制。

本次新增默认起步（第 2 步）、DeepSeek 默认多文件导入与具体分支接续（第 30–33 步）尚未真实运行，也未为此新增 GitHub Actions 运行。`python3 -m unittest discover -s desktop/tests -p 'test_native*.py' -v` 可在不启动 GUI/socket 的情况下检查动作契约：默认起步仅在隔离目录操作、实际初始化证据缺失/弹窗/错误页面拒绝；真实双文件选择顺序、缺选/失焦/重复路径/多余文件拒绝、原生 Open 不重发、可见分支键盘选择与遮挡/值不符拒绝、后台运行不能当完成，以及失败/暂停/进度错误/第二次确认拒绝。这些本地检查只验证脚本，不代替原生产品验收。

读取状态与定位元素允许有界传输恢复；点击、输入、创建会话或写入操作不会自动重发。系统缺依赖、控件不可用或数据断言失败都会使验收失败，不静默跳过。

空搜索状态的文字和定位器由 `native-ui-contracts.json` 同时供原生脚本与真实模块DOM回归使用；应用代码不读取该文件。文案漂移可在无浏览器本地预检中发现，零结果与旧正文清空仍分别断言。
