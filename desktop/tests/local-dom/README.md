# 不需要浏览器与 socket 的本地 DOM 检查

先在本地执行这些快速检查，再提交浏览器或原生桌面验收。此包直接读取并执行
`desktop/ui/index.html`、`app.js`、`model.js`、`memory-management.js`，检查实际生成的
DOM 和已注册的事件处理器；不复制应用渲染实现，也不以源码正则匹配代替交互断言。

## 运行

需要 Node.js `^22.22.2 || ^24.15.0 || >=26.0.0`。在仓库根目录执行：

```sh
npm --prefix desktop/tests/local-dom ci --ignore-scripts --no-audit --no-fund
npm --prefix desktop/tests/local-dom test
```

首次安装从官方 npm registry 获取已锁定的开发依赖；测试运行不需要联网、浏览器下载、
HTTP 服务或 socket；不读取真实资料库，也不调用外部 AI。若环境的默认 npm 缓存目录
不可写，可给安装命令追加 `--cache /tmp/recallcard-local-dom-npm-cache`。

`npm test` 使用 Node 内置测试器和 `--test-isolation=none`，避免为每个测试文件创建
测试子进程。每个用例仍使用独立的 jsdom Window 和 ES 模块实例。Node 会提示
`VM Modules is an experimental feature`；这是加载原始 ES 模块所需的实验性 API 提示，
不是浏览器或原生 IPC 的验收结果。

依赖只位于本目录：`jsdom` 精确锁定到 `30.1.2`，`package-lock.json` 固定传递依赖。
`node_modules/` 已在本目录的 `.gitignore` 排除。桌面应用与扩展运行时不引入 jsdom，
也不需要修改原有的包配置和浏览器测试。

## 检查内容

- 实际首页、导航、资料库选择、导入及确认按钮存在
- 导入样本同时包含角色、来源平台、原始时间、来源会话和正文
- 特别防止把 `.sample p` 当作唯一正文：来源和时间说明增加后，它匹配多个段落。
  正文断言定位样本内最后一个直接子段落，并验证只有一个纯文本节点
- 恶意文件名、标题和正文保持原文，不生成图片、脚本、iframe 或行内事件属性
- ZIP 默认不勾选会话；显示角色数量、覆盖范围、跳过项和附件限制
- 空批次或超过 5000 条时禁止预览；原生命令只带勾选的会话 ID
- 预览、取消最终确认、返回选择、改变格式及文件改变都不会产生意外写入
- 导入最终确认期间禁用重复点击，下一批重新从未选状态开始
- 记忆保护批准默认关闭；仅允许已审阅字段进入变更请求
- 正文、标签、保护设置和遗忘原因的变化立即撤销旧审阅与批准
- 已打开最终确认之后内容发生变化，旧确认回调仍不能写入
- 整理结果的受保护批准、返回修改和最终确认流程

`fixtures.mjs` 沿用相邻浏览器测试中的公开合成资料结构，三个消息角色和共享来源影响
范围均为测试数据。原生命令在 Tauri 调用边界记录参数，并返回明确列出的合成响应；
未知命令会使测试失败。测试不执行 Rust、读取真实文件选择或调用剪贴板。

## 清楚区分验收边界

这些是 **DOM 与事件处理合同检查**，不能算作真实 Chromium/WebKit 或 Tauri 验收。

- jsdom 实现表单属性、选择器、节点及事件；不验证布局、CSS、屏幕像素、键盘输入法、
  可访问性树、真实鼠标命中或浏览器安全策略
- jsdom 缺少 `dialog.showModal()` 和 `close()`。本测试仅模拟 `open` 属性，
  不验证原生模态层、焦点锁定、Escape、关闭事件或背景交互限制；未改写其他 DOM 方法
- “最终确认后输入变化”用例故意程序化触发输入事件，检查旧回调保护，不能据此推断
  用户可以点击原生模态框后面的控件
- 使用 `runScripts: 'outside-only'` 且不启用外部资源加载。只从本地白名单加载上述
三个真实 ES 模块。恶意样本的主要证据是 DOM 中没有可执行节点/属性，不能只看
  注入脚本是否执行来宣称浏览器 XSS 防护已经验收
- Tauri IPC、原生文件选择、剪贴板、实际文件变动检测、真实 ZIP 解析及写入由其他
  Rust/桌面测试验证；本包只验证界面展示与调用意图
- 现有 `desktop/tests/*.test.mjs` 的真实浏览器测试和原生桌面验收仍应独立运行

实施时参考 [jsdom 官方说明](https://github.com/jsdom/jsdom)：使用各自隔离的 Window
上下文，不把 jsdom Window 合并到 Node 全局；遵守其脚本执行、外部资源和布局限制。

## 本次本地结果

2026-10-07，Node.js 24.19.0：14 项通过，0 项失败、跳过或取消。运行时不启动浏览器，
不改变应用文件。依赖安装与测试是不同阶段，安装需要访问官方 npm registry。
36 个锁定依赖的来源均已核对为 `registry.npmjs.org`。

在临时隔离副本中分别把正文改为 `innerHTML`、把受保护批准改为默认勾选，相关测试
均按预期失败；实际应用文件没有变化。这两次负向验证确认断言能拦住目标回归。

运行期设有 Node 网络护栏：连接、监听或创建 UDP socket 的请求立即让测试失败，
即使应用捕获了该错误也会在用例清理时被报告。当前环境不允许 `ptrace`，因此没有
系统调用追踪结果；这里的无网络保证来自禁用外部资源、模块白名单及上述护栏，
不声称做过操作系统级网络追踪。
